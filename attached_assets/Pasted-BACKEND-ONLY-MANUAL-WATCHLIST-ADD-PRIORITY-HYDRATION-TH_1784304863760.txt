BACKEND ONLY — MANUAL WATCHLIST ADD PRIORITY HYDRATION + THEME ASSIGNMENT FIX

Backend repo only.

Do not touch frontend.
Do not rewrite the Watchlist system.
Do not replace existing FMP/Tradier/technical refresh pipelines.
Do not create duplicate refreshers if existing ones can be reused.
Do not bypass the existing FMP budget governor / call spacing.
Do not break weekly/off-hours fundamentals refresh.
Do not change Confluence scoring.
Do not change Options Flow.

Problems:

1. Newly added manual tickers are lagged and do not appear immediately/reliably.
2. Newly added tickers do not consistently get technical and fundamental data right away.
   - Technical data can take minutes.
   - Fundamental data may wait until the weekly refresh.
3. Manually added tickers need to skip to the front of technical/fundamental queues.
4. Adding a new watchlist / multiple tickers should priority-hydrate all of them quickly.
5. Theme assignment dropdown appears after manual add, but the backend persistence/update path appears broken or incomplete.

Goal:

Manual watchlist additions should immediately:
- persist the ticker
- return it in watchlist responses
- enqueue priority technical hydration
- enqueue priority quote hydration
- enqueue priority FMP fundamentals/profile hydration
- allow theme assignment to persist correctly

PART 4 — MULTI-TICKER / NEW WATCHLIST ADD
==================================================

When multiple tickers are added:

- persist all immediately
- return all immediately with hydration pending status
- enqueue all at priority
- dedupe symbols already in queues
- batch where existing APIs support batch
- respect FMP and Tradier pacing
- process these before normal background refresh backlog

Add status metadata:

hydration_status:
{
  quote: "pending/running/done/error",
  technical: "pending/running/done/error",
  fundamentals: "pending/running/done/error",
  last_error: null | string,
  last_updated: timestamp
}

Do not block the HTTP response waiting for every API call to finish unless the existing add endpoint is designed to do so. Preferred:
- return immediately
- background priority job hydrates
- frontend can refetch/poll lightly or receive updated watchlist after completion
