Server is running cleanly. Here's what was fixed:

Root cause: FastAPI's import response includes updated_holdings — the full lot-detail array for every position across both accounts. For a single-account import this is manageable, but for a second import (Roth + Individual Brokerage combined) the payload balloons to potentially hundreds of KB of nested JSON. Vite's dev proxy cuts the stream mid-response, so the browser receives a truncated JSON string → "Unexpected end of JSON input".

What changed in the Express route:

Response is now read as raw text first — if FastAPI sends a partial or empty body, we catch it and return a proper { success: false, error: "..." } instead of crashing the stream
updated_holdings is stripped before sending back to the browser — the server already wrote it to stock-holdings.json and the browser refetches from there. The browser never needed the raw array
204 status normalised to 200 — HTTP forbids a body on 204 responses, which silently drops it
preview array preserved for preview-mode responses (it's small — just a few rows)
The response the browser now gets is a lean summary object (success, symbols_imported, symbols_closed, sells_found, options_skipped, closed_trades_created, etc.) regardless of how many combined holdings exist in FastAPI. You should be able to upload both CSVs cleanly now.
