Implement a new backend API surface for a Stock Compare feature on the existing CaelynAI backend FastAPI server.

The frontend will call this from the existing Fundamentals page. The user should be able to enter up to 15 stock tickers, select a financial metric, choose a time range, and receive normalized chart-ready comparison data.

Goal

Create backend endpoints that support:

Ticker autocomplete/search.
Multi-ticker financial metric comparison.
Recent news per ticker.
Cached FMP-backed financial data.
Optional SEC filing enrichment where useful.

Primary source should be the paid FMP API. Use Finnhub/SEC EDGAR only as fallback/enrichment, not the default lane.

Relevant paid FMP capabilities available:

300 API calls/minute.
Up to 5 years historical data.
US coverage.
Annual fundamentals and ratios.
Company profile/reference data.
Financial market news.
Stock quote / price change.
Limited market cap / batch market cap.
Limited income statement, balance sheet, cash flow statement.
Limited key metrics, financial ratios, TTM metrics, growth endpoints.
Full SEC filings endpoints.
Limited earnings report/calendar.
Full company search endpoints.
New Routes

Add these routes under an existing fundamentals/stocks router if one exists. Otherwise create a dedicated router such as:

backend/routes/stock_compare.py

and mount it in the FastAPI app.

Use route prefix:

/api/fundamentals/compare

Endpoint 2: Compare Metrics
POST /api/fundamentals/compare
Request body
{
  "symbols": ["INTT", "TRT", "NNBR"],
  "metric": "revenue",
  "period": "annual",
  "range": "all"
}
Supported range values
1M, 3M, 6M, YTD, 1Y, 3Y, 5Y, 10Y, MAX, ALL

For fundamentals, annual/quarterly data will not map perfectly to 1M/3M/6M. For short ranges, return the most recent available annual/quarterly points and let the frontend display a helpful “financial statement data updates quarterly/annually” note. Do not fake monthly data.

Metric Calculation Rules

Use raw FMP fields when available. Calculate only when the formula is straightforward.

Revenue Growth

Prefer FMP growth endpoint. Fallback:

(current revenue - previous revenue) / previous revenue

Return as decimal:

0.128 = 12.8%
Gross Margin
grossProfit / revenue
Profit Margin

Prefer netProfitMargin from ratios. Fallback:

netIncome / revenue
Free Cash Flow

Prefer freeCashFlow from cash flow statement. Fallback:

operatingCashFlow - capitalExpenditure

Be careful: capex may be negative in FMP data. Normalize correctly.

Total Debt

Prefer balance sheet totalDebt. Fallback:

shortTermDebt + longTermDebt
P/S Ratio

Prefer FMP ratios/key metrics. Fallback:

marketCap / revenue
P/E Ratio

Prefer FMP ratios/key metrics. Fallback:

marketCap / netIncome

Avoid calculating if denominator is zero or negative. Return null and a warning.

Caching Strategy

Add caching because the user may compare up to 15 tickers, and this can fan out quickly.

Suggested TTLs:

ticker search: 24 hours
company profile: 24 hours
annual financial statements: 24 hours
ratios/key metrics: 24 hours
market cap / quote: 15 minutes
stock news: 30 minutes
SEC filings metadata: 6 hours

Cache key format:

stock_compare:{endpoint}:{symbol}:{period}:{limit}

Examples:

stock_compare:income_statement:INTT:annual:40
stock_compare:ratios:TRT:annual:40
stock_compare:profile:NNBR
stock_compare:news:INTT:10

Use existing project cache utilities if available. Do not introduce a new cache layer unless necessary.

API Call Efficiency

For 15 symbols, do not blindly call every endpoint for every metric.

Use metric-aware fetching:

If metric is revenue

Fetch only:

profile
income statement
quote/market cap if needed for snapshot
If metric is free_cash_flow

Fetch only:

profile
cash flow statement
If metric is total_debt

Fetch only:

profile
balance sheet
If metric is ps_ratio or pe_ratio

Fetch:

profile
key metrics / ratios
market cap fallback if needed
income statement fallback if needed
If metric is recent_news

Fetch:

profile
stock news

Do not fetch SEC filings unless:

FMP financial statement data is missing.
CIK enrichment is needed.
The user selects or later requests filings.
SEC EDGAR Enrichment

SEC EDGAR should be fallback/enrichment only.

Use SEC when:

FMP returns no company CIK but SEC lookup can resolve it.
A ticker’s latest financial values are missing.
You want to add a “latest filing” metadata object.

Optional response addition:

"filings": {
  "INTT": [
    {
      "form": "10-K",
      "filingDate": "2026-03-15",
      "accessionNumber": "...",
      "url": "https://www.sec.gov/Archives/..."
    }
  ]
}

Respect SEC limit of 10 requests/second from the project API limits doc.

Error Handling

Return partial data instead of failing the whole request.

Example:

{
  "series": [...],
  "meta": {
    "warnings": [
      "NNBR missing free cash flow for 2020.",
      "TRT P/E ratio unavailable because net income is negative."
    ]
  }
}

If a symbol is invalid:

{
  "invalidSymbols": ["ABCXYZ"],
  "validSymbols": ["INTT", "TRT"]
}

Frontend should be able to render valid symbols even if one ticker fails.

Validation

Backend should enforce:

max symbols: 15
min symbols: 1
symbols: uppercase A-Z, dot, hyphen allowed
metric: must be allowlisted
period: annual or quarterly
range: allowlisted

Return 400 for invalid request shape.
