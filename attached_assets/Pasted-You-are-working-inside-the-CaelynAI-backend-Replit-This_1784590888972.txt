# Part 2 — Correct Business Quality formulas

## FCF Conversion

Canonical formula:

TTM Free Cash Flow / TTM Net Income

Rules:

* Only calculate when TTM net income is materially positive.
* Negative net income is `not_meaningful`.
* Zero or immaterial net income is `not_meaningful`.
* Do not use `abs(net_income)` as the validity gate.
* Add a canonical missing/not-meaningful reason.
* Ensure an old positive FCF Conversion is not carried forward when the current result becomes not meaningful.

## Diluted Shares Growth YoY

Current code compares one quarter with one quarter.

Replace it with:

* Current TTM average diluted shares across the latest four valid quarters
* Prior TTM average diluted shares across the preceding four valid quarters
* Growth = current TTM average / prior TTM average − 1

Do not sum share counts.

Require eight correctly matched quarters.

Store provenance explaining that quarterly weighted-average diluted shares were averaged across each four-quarter window.

## Operating Margin fallback

Keep the direct FMP TTM value as first priority.

When it is absent, derive:

TTM operating income / TTM revenue

Record direct versus derived source.

# Part 3 — Correct Growth Quality formulas

## Revenue Acceleration

Continue using:

Latest-quarter YoY revenue growth minus previous-quarter YoY revenue growth

But match quarters through fiscal year/quarter/date identity.

## Gross Margin Change YoY

Continue using current TTM margin minus prior TTM margin.

Require eight complete matched quarters.

## Incremental Operating Margin

Formula:

Change in TTM operating income / change in TTM revenue

Rules:

* Require current TTM revenue to be greater than prior TTM revenue.
* Negative revenue change is `not_meaningful`.
* Zero or immaterial revenue change is `not_meaningful`.
* Add a denominator threshold based on both an absolute floor and a reasonable percentage of prior revenue.
* Do not calculate merely because `abs(delta_revenue)` is above $1 million.
* Ensure a stale previous value cannot survive beside a current not-meaningful state.

# Part 7 — Replace blanket Quality carry-forward

The current `_QUALITY_CARRY_FIELDS` loop carries any absent field forward regardless of why it is absent.

That can preserve stale and contradictory values.

Implement source-aware carry-forward.

Carry a prior value only when:

* The responsible endpoint genuinely failed, timed out, returned non-200, or returned an unusable empty payload
* No valid current not-meaningful state was produced
* No current value explicitly replaced it

Do not carry a prior numeric value when the current calculation legitimately becomes not meaningful.

Required cases:

## P/FCF

When current TTM FCF is zero or negative:

* Remove/omit current P/FCF
* Set not-meaningful reason
* Do not carry the old positive P/FCF

## Altman Z

When the company is classified as financially inappropriate:

* `Altman Z-Risk = not_meaningful`
* Remove/omit numeric Altman Z-Score
* Do not carry an old score

## Forward valuation

When current forward EPS, revenue or EBITDA is zero/negative:

* Return the corresponding not-meaningful reason
* Do not carry the old multiple

When the analyst-estimates endpoint actually fails transiently:

* Prior value may be carried with stale/source metadata

## Revision fields

* A revision value and `history_building` reason must never coexist.
* A current revision value must clear an old missing reason.
* A current missing reason must clear an old revision value unless the entire source endpoint failed and stale carry-forward is explicitly intended.

Track per-endpoint outcomes, for example:

* success_with_data
* success_no_data
* not_entitled
* transient_failure
