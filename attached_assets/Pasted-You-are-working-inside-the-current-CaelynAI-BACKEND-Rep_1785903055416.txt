## Confirmed failure in the previous correction

The present implementation in `canonical_history_service.py` does the following:

* `_completed_daily_bars()` excludes every bar dated on the current New York calendar date.
* `_compute_price_metrics_from_completed()` sets `latest_close = completed[-1][1]`.
* It calculates `change_7d` and `change_30d` using that historical `latest_close`.
* The percentages are persisted into canonical-history metadata and subsequently consumed by the Watchlist path.

That means the calculation is effectively:

`stale_or_previous_completed_canonical_close / older_canonical_close`

It is not necessarily:

`current_watchlist_price / correct_historical_comparison_close`

The previous report itself proved this failure:

* AAPL was calculated only through 2026-07-14.
* NVDA was calculated only through 2026-07-14.
* MSFT was calculated only through 2026-07-29.
* The user’s actual current-price-based 30-day figures are materially different.

The previous validation table did not contain the required independent benchmark values or absolute differences. It therefore did not satisfy the prior task.
