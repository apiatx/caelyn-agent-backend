Do not call any LLM APIs: no OpenAI, Anthropic, Grok, Perplexity, etc.
Do not use /stable/historical-price-eod/full.
Do not reintroduce ETF quote loops.
Do not modify saved screens or daily screens unless needed to avoid saving invalid/empty custom screens.

Goal:
Fix Screener Hub thematic screening systemically across every theme in the dropdown.

This is not a Memory & Storage-only issue.
Do not patch themes one by one.

Problem:
The default theme works because it has already been enriched/hydrated. But when the user selects another theme from the dropdown, many themes return weak rows with missing market cap, sector, industry, price, volume, and exchange.

The custom theme screener must work the same way as the default theme.

Desired behavior:

Default theme = daily recommended theme based on RS + data quality.
Explicit user-selected theme = run/serve that exact theme through the same screener pipeline.
Every theme in the dropdown should have consistent filtering, hydration, non-equity exclusion, and data-quality rules.
If a selected theme is stale/missing/weak, backend should refresh that theme on demand, with a once-per-theme-per-day FMP guard.
User clicking a different theme should not return garbage ETF placeholders or rows with missing required fields under active filters.
No LLM calls.

Part 2 — Create one canonical theme screen pipeline

Implement or refactor toward one shared function used by both default and explicit themes, conceptually:

build_theme_screen(theme_key, filters, score_mode, refresh_policy)

It should:

Resolve and validate theme_key
Load latest cached theme universe/snapshot
Determine staleness/data quality
If stale or weak and refresh allowed, refresh that theme once per 24h
Hydrate rows from existing caches:
screener metadata
screener_fundamentals_cache
quote cache
options cache
snapshot metadata
Exclude non-equity junk globally
Apply market cap, min volume, exchange filters
Rank/score rows
Return clean response metadata

Both:

default daily theme
explicit user-selected theme

must use this same path.

Do not leave selected theme requests on a weaker ETF/LKG-only path.

When user explicitly selects a theme:

missing

Part 4 — Required field policy for screenable stock rows

For thematic stock screens, define minimum screenable row requirements.

A row should not be considered screenable if it is missing critical fields after hydration.

Critical fields:

symbol
price
market_cap when market cap filter is active
volume when min volume filter is active
sector/industry if available from fundamentals cache, but do not hard-fail solely for sector if all other data is good

When market cap filter is active:

missing market_cap rows must be excluded
unknown market cap is not “under $10B”

When min volume filter is active:

missing volume rows must be excluded
unknown volume is not “above min volume”

When exchange filter is active:

missing exchange rows should be excluded unless there is an intentional documented policy to keep unknowns

Add response metadata:

rows_excluded_missing_market_cap
rows_excluded_missing_volume
rows_excluded_missing_exchange
unknown_market_cap_policy
unknown_volume_policy
unknown_exchange_policy

Part 6 — Data quality gating across every theme

For every selected theme response, compute:

returned_rows
rows_with_market_cap
rows_with_price

rows_with_sector
rows_with_industry

metadata_coverage_pct

If returned rows are weak:

return low_result_quality=true
return result_quality_warning

If returned_rows = 0:

return empty rows with a clear JSON message
do not fallback to default theme
do not return random ETF placeholders
