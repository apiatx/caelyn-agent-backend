5. Relative strength calculation for themes

Use the same logic already used for broad sectors, but run it over the theme ETF basket.

Add fields like:

{
  "relative_strength_score": 0-100,
  "momentum_rank": 1,
  "trend_state": "Leadership | Improving | Neutral | Weakening | Lagging",
  "rotation_state": "Accelerating | Stabilizing | Fading | Reversing"
}

Suggested scoring model:

relative_strength_score =
  35% 1M performance percentile
  25% 3M performance percentile
  20% 5D performance percentile
  10% distance above/below 50D moving average
  10% 20D trend acceleration

Keep it simple first. Don’t build a NASA launch console unless it prints money.

6. Cache aggressively

Theme ETF data does not need to hit APIs every frontend refresh.

Add caching like:

sector_theme_performance_cache_ttl = 15 minutes during market hours
sector_theme_performance_cache_ttl = 60 minutes outside market hours
agent_theme_rotation_cache_ttl = 6-12 hours

Use existing backend cache patterns if available.

Do not call expensive AI models just because the user toggled between Sectors and Themes.

7. Data source preference

Use existing market data services already wired into the backend.

Preferred order:

Existing internal quote/history adapter if present
FMP for ETF quotes/historical EOD when cheap and cached
TwelveData only if already used for technicals and not rate-bottlenecked
Finnhub ETF profile/holdings/exposure only for metadata enrichment, not repeated performance polling
Avoid Polygon unless the existing sector system already uses it and rate limits are protected

Important: FMP and Polygon have tighter limits, so do not loop over 80 ETFs repeatedly on every page load. Cache or batch wherever possible.
