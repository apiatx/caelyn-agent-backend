Make the Screener Hub Thematic tab a real hidden-gem discovery engine using FMP Stock Screener industry mapping, while protecting FMP usage and avoiding page-load API calls.

Current problems:
1. Thematic Screener is still too leader/mega-cap heavy.
2. Semiconductors should surface lower-cap and supply-chain momentum names, not just NVDA/AVGO/AMD/TSM/ASML.
3. Theme dropdowns like drones previously produced 502s; they must return safe JSON.

Core architecture:
- FMP Stock Screener is a multi-row discovery endpoint.
- Use one FMP screener call per mapped industry/filter, not one call per ticker.
- Do not use a single giant no-sector/no-industry $50B screen as the primary discovery source.
- Do not call FMP Stock Screener during normal user page loads or dropdown changes.
- Use FMP Stock Screener only during scheduled rebuilds or admin rebuilds.
- Page loads should read cached snapshots/returns/fundamentals only.
- If cache is cold, return partial/null fields safely, not live heavy FMP calls.

Part 2 — Use FMP Stock Screener as a cheap wide-net discovery source

Implement or update an FMP screener helper used only in scheduled/admin rebuilds.

Expected behavior:
For each theme:
1. Load theme_fmp_industry_map.json.
2. For each mapped industry, make one FMP Stock Screener API call with filters:
   - industry=<mapped industry>
   - marketCapLowerThan=<theme market_cap_upper_default, default 50000000000>
   - isEtf=false
   - isFund=false
   - isActivelyTrading=true
   - limit=<conservative limit, e.g. 500 or 1000 depending endpoint support>
3. Optionally call by sector only if industry calls are too thin, but prefer industry-specific calls.
4. Do not use one giant all-market screen as the primary source.
5. Use the returned fields directly:
   - symbol
   - companyName
   - marketCap
   - sector
   - industry
   - beta
   - price
   - volume
   - exchange
   - exchangeShortName
   - country
   - isEtf
   - isFund
   - isActivelyTrading
6. Cache this returned metadata in the Screener Hub snapshot/fundamentals metadata if practical.
7. Dedupe by symbol globally.
8. Exclude ETFs/funds from final rows.
9. Filter obvious bad symbols:
   - inactive
   - ETFs/funds
   - preferreds/warrants/units where detectable
   - junk exchanges/countries where practical
10. Do not make additional per-ticker FMP profile/historical/metrics calls for every FMP screener result.

Correct flow:
FMP screener call per mapped industry
→ many candidate tickers returned
→ cache metadata
→ dedupe
→ rank hidden gems
→ only enrich top/missing candidates later if cache-first and within budget

Incorrect flow:
FMP screener call
→ 500 tickers
→ 500 profile calls
→ 500 historical calls
→ 500 metrics calls

Do not do the incorrect flow.
