Part 2 — Add refresh schema/config versioning

Add a refresh/pipeline version marker for thematic universe snapshots.

Example:
THEMATIC_REFRESH_SCHEMA_VERSION = "theme_screener_v2_inline_fmp_industry_map"

When building or refreshing a theme universe, write into snapshot metadata:

* refresh_schema_version
* fmp_industries_used
* fmp_screener_used: true/false
* refresh_reason
* build_pipeline_version

When serving a selected theme, compare the latest snapshot metadata to the current version.

If latest selected-theme snapshot is missing the current refresh_schema_version or was built with an old version:

* treat it as stale/invalid for selected-theme use
* allow exactly one immediate inline refresh even if generated_at is within 24h
* then store the new version metadata so future clicks obey the 24h cap again

This solves the issue where the 24h cap preserves bad snapshots created before code/config fixes.
