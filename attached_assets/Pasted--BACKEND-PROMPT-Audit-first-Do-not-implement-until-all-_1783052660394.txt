PART B — Backend theme classification design

Implement only after audit confirms the safest path.

Rules:
1. Reuse existing symbol-level theme mapping first.
2. For one manual ticker add:
   - check existing symbol mapping
   - if missing, use FMP company profile sector/industry if already available or through the existing controlled FMP path
   - map to closest canonical theme if deterministic mapping exists
   - only use LLM if FMP/profile mapping is insufficient
3. For CSV upload or 10+ manual tickers:
   - batch only unmapped symbols
   - include ticker, company name, FMP sector, FMP industry, exchange, CSV industry, and description if cached
   - include the canonical theme taxonomy
   - LLM must return strict JSON only
   - persist symbol → canonical_theme_id / canonical_theme_name / confidence / source / refreshed_at
4. Do not classify already mapped symbols.
5. Do not call LLM on page render.
6. Do not call LLM on normal Watchlist GET.
7. If LLM unavailable, mark Needs Theme and allow retry.
8. Preserve raw CSV industry separately as csv_industry/raw_industry.
9. CSV industry must not overwrite canonical theme.
10. Old and new watchlists should share symbol-level mappings.

Provider config:
Add env-configurable provider/model, for example:
- THEME_CLASSIFIER_PROVIDER=gemini/openai/deepseek/grok
- THEME_CLASSIFIER_MODEL=<model_name>

Preferred default:
- cheap fast model suitable for structured JSON batch classification
- recommend Gemini Flash or OpenAI mini/nano style model if configured
- do not default to Claude
