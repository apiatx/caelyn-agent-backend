This is a critical options-flow architecture fix. Do not broaden scope.

PRIMARY GOAL
Fix the Home `Unusual Options Flows` section and the main `Options Flow` page so options-flow data is always displayed from a real cached live snapshot, instead of frequently showing empty/no-data while a slow scan runs.

CURRENT PROBLEM
The recent implementation is still too slow and not truly real-time enough for UX:

* inline Home live scan timed out at 25s and returned zero data
* fallback background scan is blocked by a global sequential semaphore
* 8 tickers take ~40–80s
* one background run took ~185.6s
* Home can therefore render no options data while waiting for the scan/cache to populate

This is not acceptable.

AUDIT FIRST
Inspect the current options-flow architecture and identify exactly:

1. where the global sequential semaphore is defined and why it serializes the scan
2. what the current scan universe is for:

   * Home unusual options
   * Options Flow page tabs
3. what the current cache layers are:

   * fast cache
   * LKG cache
   * tab caches
4. under what exact conditions Home returns empty / "no unusual options activity"
5. whether the empty state currently means:

   * true no-results
   * cold cache
   * refresh in progress
   * timed out scan
6. whether the Options Flow page and Home are using the same scoring logic but different cache behavior
7. whether Tradier/Public requests are being made per ticker / per contract in an inefficient pattern

IMPLEMENTATION TARGET
Move to an always-available stale-while-revalidate architecture.

REQUIRED BEHAVIOR
A. Home Unusual Options Flows

* must always return the best available recent snapshot
* should never return empty if any valid recent LKG snapshot exists
* if refresh is in progress, return stale snapshot immediately with metadata:

  * updated_at
  * refresh_in_progress
  * age_seconds
  * source
* only return true empty if a completed scan found no unusual flows OR there has literally never been a successful snapshot

B. Options Flow page

* should use the same basic underlying call/scoring family
* should also benefit from the same always-available snapshot principle
* tabbed page can still run broader scans, but should not frequently appear empty while recomputing

C. Refresh architecture

* do NOT use any paid AI API
* use only Tradier / Public / existing internal scoring logic / cheap existing market-data helpers
* create a persistent refresh model instead of lazy request-triggered-only warmup:

  * fast Home snapshot refresh every 1–3 minutes OR as fast as safely possible
  * broader page/tab snapshot refresh on a slower cadence if needed
* startup warm immediately; do not wait 30s/120s before first meaningful pass if avoidable

D. Concurrency

* replace the global sequential bottleneck with bounded concurrency
* stay within Tradier limits, but do not process one symbol at a time if the API budget allows substantially more
* make concurrency explicit and configurable

E. Scan scope

* create a lighter fast scan for Home top unusual flows
* create/keep broader scans for tabbed Options Flow page
* share core scoring logic, not necessarily identical breadth

F. Cache strategy

* implement explicit snapshot metadata:

  * updated_at
  * source
  * refresh_in_progress
  * stale
  * stale_age_seconds
  * result_count
* Home and Options Flow should consume these snapshots cleanly
* stale-but-usable data is better than blank

VERY IMPORTANT
Do NOT let "no unusual options activity detected" be returned when the real condition is "scan not complete yet" or "cache cold".

VERIFY
Before finishing, prove with real checks:

1. Home request returns non-empty options data from LKG or fresh cache even during refresh
2. Home request latency is low and does not block on full live scan
3. Options Flow page/tab caches also have usable snapshots during recompute
4. global sequential bottleneck is removed or materially relaxed
5. no AI API is used anywhere in this path
6. return payload distinguishes:

   * no_data_yet
   * refresh_in_progress
   * stale_but_available
   * live_ok
   * true_zero_results
