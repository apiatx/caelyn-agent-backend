Both fixes are clean and live. Here's exactly what was wrong and what changed:

Root cause — the rate limiter was broken in two ways:

validate: { trustProxy: false } was missing. Without it, express-rate-limit throws a ValidationError on the very first request to any rate-limited /api/* route, which bypasses the custom handler and instead falls through to the error middleware — returning the raw error string "Rate limit exceeded" regardless of how many requests have actually been made.

The limit of 100 per 15 minutes is far too low for this app. The realtime-quotes, market-tape, and background pollers alone make well over 100 API calls in 15 minutes during normal use. So even once the ValidationError was fixed, the rate limiter would still fire on legitimate portfolio operations.

What was changed:

security/middleware.ts — added validate: { trustProxy: false } to both limiters, raised the cap to 2000 dev / 500 production (15-min window)

stocks-portfolio.tsx — sell flow now optimistically writes the backend response straight into the React Query cache the moment the 200 comes back, before touching local JSON. A full close removes the holding from cache instantly; a partial trim updates the share count immediately. The local JSON DELETE/PUT still runs after (now that the rate limiter isn't broken it will succeed), but it's non-blocking — the UI no longer depends on it to show the updated state.
