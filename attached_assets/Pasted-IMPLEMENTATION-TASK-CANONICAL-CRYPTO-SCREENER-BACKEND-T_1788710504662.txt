already exists, but do not invent additional parallel endpoints.

3. Structure the service so the Caelyn agent can call the SAME service later.

==================================================
TECHNICAL CALCULATIONS
==================================================

All moving averages use COMPLETED daily closes only.

Never include an incomplete current UTC day in an SMA.

Compute:

sma_50
sma_150
sma_200

pct_vs_sma_50
pct_vs_sma_150
pct_vs_sma_200

where:

pct_vs_sma_N =
    (current_market_price / sma_N - 1) * 100

Compute:

above_sma_50
above_sma_150
above_sma_200

above_all_3 =
    current_price > sma50
    AND current_price > sma150
    AND current_price > sma200

bullish_ma_stack =
    sma50 > sma150
    AND sma150 > sma200

Also compute:

sma_50_rising
sma_150_rising
sma_200_rising

Use a deterministic slope comparison against the corresponding SMA value five
completed daily observations earlier.

==================================================
BREAKOUT / HOLD STATE
==================================================

We want useful CURRENT trading states, not a stale once-daily label.

For each N in 50, 150, 200:

fresh_breakout_N =

    current_market_price > latest completed-day SMA_N

AND

    at least one of the previous 3 COMPLETED daily closes was at or below its
    corresponding SMA_N

This allows a breakout that occurred today or very recently to remain visible.

holding_above_N =

    current_market_price > SMA_N

AND

    the previous 3 completed daily closes were all above their corresponding
    SMA_N

AND

    fresh_breakout_N is false

Do not invent a subjective "consolidation score" in this task.

A deterministic HOLD state is enough.

Generate one backend setup_label using this priority:

1. "200D BREAKOUT"
2. "150D BREAKOUT"
3. "50D BREAKOUT"
4. "ABOVE ALL · BULLISH STACK"
5. "ABOVE ALL · HOLD"
6. "ABOVE 200D"
7. "BELOW 200D"

Only emit a label when the required history is complete.

Otherwise:

setup_label = null

CURRENT 24H VOLUME

24H VOLUME CHANGE

Use CMC's existing volume_change_24h value directly:

volume_change_24h_pct

Do not reconstruct this from unrelated buckets.

VOLUME / MARKET CAP

volume_to_market_cap_pct =

    CMC volume_24h / CMC market_cap * 100

7-DAY VOLUME METRICS

Use comparable CoinGecko volume observations from the CoinGecko historical
series.

volume_delta_7d_pct =

    (
      average(latest 7 completed daily volume observations)
      /
      average(previous 7 completed daily volume observations)
      - 1
    ) * 100

vol_x_7d =

    current CoinGecko comparable 24h volume
    /
    average(previous 7 completed CoinGecko daily volume observations)

Keep the provider methodology internally consistent for VolX.

Do not mix a CoinMarketCap numerator with a CoinGecko denominator for VolX.
