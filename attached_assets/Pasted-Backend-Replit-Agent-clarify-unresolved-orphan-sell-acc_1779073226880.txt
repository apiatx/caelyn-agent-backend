But this statement needs correction:
"The synthetic injection fix will resolve orphan sells automatically on the next import because the first import persists those tickers' positions into the DB."

That is only true if those orphan-sell tickers exist in pre-import DB holdings or are recreated as open positions after import.

For sell-only tickers that are fully closed in the CSV and have no matching buy in CSV or DB, the engine cannot compute accurate cost basis or realized P&L. Re-importing the same CSV will not solve that.

Please update the import logic/diagnostics so it distinguishes:

1. Resolved orphan sells
- sell has no buy in CSV
- but existing DB holding provides opening shares/avg_cost/entry_date
- synthetic lot injected successfully
- P&L computed

2. Unresolved orphan sells
- sell has no buy in CSV
- no matching existing DB holding/basis
- cannot compute accurate realized P&L
- must remain accounting_error or needs_basis_review

3. Buy-close-reopen pattern
- old lot closed
- fresh later lot opened
- final status open only, not partially closed

Required output fields:
- orphan_sells_resolved
- orphan_sells_unresolved
- orphan_sells_unresolved_symbols
- needs_basis_review_symbols
- basis_source_by_symbol:

For unresolved orphan sells, do not claim they will resolve on next import unless the missing opening buy or pre-import DB holding exists.
