# Proven defect 1 — background rebuild destroys the LKG before success

Current `_rebuild_bulk_lkg_bg()` does approximately:

```python
_BULK_LKG.pop(watchlist_id, None)
await get_by_id_endpoint(watchlist_id)
```

This is wrong.

It creates two failure modes:

```text
background rebuild fails
→ valid prior LKG is lost

background rebuild is in progress
+ another browser GET arrives
→ no LKG exists
→ browser can enter full inline enrichment
```

The current test suite explicitly asserts:

```text
rebuild failure leaves LKG absent
```

That assertion must be reversed.
