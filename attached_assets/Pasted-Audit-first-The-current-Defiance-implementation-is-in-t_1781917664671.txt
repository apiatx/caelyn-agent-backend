Audit first. The current Defiance implementation is in the wrong place conceptually and the output is not correct.

Current issue:
The frontend screenshot shows the Underlying column as “—” while the Defiance ETF badge shows values like AMA · 2X Long, AMKL · 2X Long, etc. That is wrong. The primary row symbol must be the clean underlying stock ticker. The Defiance ETF ticker is metadata only.

New product location:
This feature should belong to the Strategy page, not Watchlist.

Backend goal:
Fix/replace the current Defiance 2X endpoint so it returns a clean underlying-centric response suitable for a Strategy page tab named “Defiance”.

Critical requirements:

* Do NOT track/chart/quote the Defiance ETF as the primary asset.
* The row symbol must be the underlying stock ticker.
* The Defiance ETF ticker must only appear in nested metadata.
* Any already-tracked underlying stock must reuse the existing canonical quote/ticker universe/cache path.
* Only underlying stocks that are not already tracked anywhere in the app may trigger a new Tradier quote call.
* Do NOT duplicate Tradier calls for tickers already present in the app’s ticker universe, watchlist, portfolio, themes, options flow cache, or canonical quote cache.
* Do NOT use an LLM.
* Do NOT manually maintain a permanent ETF list.
* Do NOT scrape live on every user request.
* Preserve existing quote/fundamental/stage/chart paths.

Audit required:

1. Find the current Defiance backend files:

   * defiance_leveraged_etfs_service.py
   * current route in watchlist_router.py
   * startup/warmup hook in main.py
2. Audit the actual Defiance API payload from:
   /wp-json/defiance/v1/etfs-explore
3. Determine whether the payload itself contains a reliable underlying ticker, target ticker, fund URL, slug, title, or metadata field.
4. If the ETF catalog payload does not directly expose the underlying ticker, fetch the individual official Defiance fund page/API detail for each leveraged-long ETF and parse the official underlying/target exposure from that source.
5. Do not assume the Defiance ETF ticker is the underlying ticker. The screenshot proves that assumption is wrong.
6. Find the existing app-level ticker universe / canonical quote cache utilities so already-tracked underlying tickers can be reused without additional Tradier calls.

Implementation changes:

1. Keep the Defiance ETF catalog refresh service, but fix its mapping contract.
2. Build rows only when a valid underlying stock ticker is found.
3. Validation rules for each row:

   * underlying_symbol is non-empty
   * defiance_etf_ticker is non-empty
   * underlying_symbol !== defiance_etf_ticker
   * underlying_symbol validates as a stock/common equity where possible
   * defiance_etf_ticker validates as an ETF/fund where possible
   * quote_source_symbol must equal underlying_symbol
   * chart_symbol must equal underlying_symbol
4. Any ETF where the underlying cannot be confidently mapped should be quarantined/excluded from the user-facing response and logged as unmapped_defiance_etf.
5. Add/rename endpoint for Strategy page:
   Preferred:
   GET /api/strategy/defiance

   GET /api/strategy/defiance-2x
