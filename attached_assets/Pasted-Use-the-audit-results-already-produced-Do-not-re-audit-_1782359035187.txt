We need to align the existing Tradier system to the intended app-wide model, but do this in phases. Do not build a separate parallel scheduler unless absolutely necessary. Use the existing TradierProvider, limiter, caches, in-flight guard, coalescing, and shared `portfolio_opts:{sym}` rows.

North-star model:
There should eventually be two central Tradier work types:

1. Quote work:

* price
* bid/ask
* volume
* quote timestamp
* quote-derived fields like VolX / volume context where applicable

2. Options work:

* expirations
* option chains
* IV
* call/put volume
* open interest
* put/call ratio
* expected move
* options score/signal

Pages are not separate Tradier scanners.

Watchlist, Portfolio, Themes, Options Flow, Sectors, Social, Screener, Strategy, ticker popup/search, and any other page needing Tradier data should eventually register symbol demand with:

* symbol
* needed data type: quote/options/both
* scope: watchlist/portfolio/themes/options_flow/sectors/social/screener/strategy/popup
* priority
* visible_now true/false

Then all pages should read the same canonical cached quote/options rows.

If AMD appears in Watchlist, Themes, Portfolio, Strategy, Social, and Options Flow Sectors, AMD should not be scanned six times. It should have one canonical quote row and one canonical options row. Multiple page scopes should raise AMD’s priority, not create duplicate Tradier calls.

Important:
Do not interpret this as “scan every ticker’s full options chain every minute.”
Instead:

* quotes refresh fastest
* options refresh on a reasonable cycle
* active visible page symbols eventually get priority
* Options Flow screener eventually gets reserved near-real-time budget
* stale/LKG rows are refreshed in the background
* last-good values stay visible until replaced by a successful refresh

But do not implement the entire north-star system in one pass.
