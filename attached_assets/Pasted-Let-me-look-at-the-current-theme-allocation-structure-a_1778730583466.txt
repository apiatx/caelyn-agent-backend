Context
Your existing GET /api/caelyn-terminal endpoint returns theme_allocation[]. When a ticker isn't in your thematic universe, it falls into a bucket like {"name": "Unclassified", "fallback_used": true, "symbols": ["SIVEF","PENG","SLOIF","IQEPF",...]}. This endpoint takes that list, classifies each one via LLM, and persists the results so future theme_allocation responses place them in named theme buckets instead of "Unclassified".

Endpoint spec
POST /api/portfolio/categorize-themes
Auth: X-API-Key header (existing key)
Content-Type: application/json

Request body:

{
  "tickers": ["SIVEF", "PENG", "SLOIF", "IQEPF", "NRGV", "SLNH", "P", "VPG", "SILC", "FPLSF"]
}

What the endpoint must do:

For each ticker in the tickers array, look up what you know about it — company name, industry, sector, description. Use whatever data source you have (FMP, yFinance, or your existing quote/company info layer).

Pass all tickers together to Claude (or your existing LLM) in a single prompt. The prompt should instruct the model to assign each ticker to the most appropriate investment theme from your existing thematic universe (the same themes already used for classified tickers like "Semiconductor Equipment", "Substrates / Packaging", "AI Networking", "Data Center Infrastructure", "Power / Cooling", "Robotics / Automation", etc.). If a ticker doesn't fit any existing theme, the model may propose a new theme name. Format the response as structured JSON.

Save each {ticker → theme} mapping to your thematic database/store so that future calls to GET /api/caelyn-terminal will return these tickers under their new theme name rather than "Unclassified". This is the same store you use to build the thematic_universe classifications.
