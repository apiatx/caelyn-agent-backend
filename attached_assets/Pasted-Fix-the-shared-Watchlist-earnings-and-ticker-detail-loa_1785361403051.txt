PROVEN ARCHITECTURAL PROBLEMS
──────────────────────────────────────────────────────────────────────────────

1. The Watchlist page calls:

   POST /api/watchlist/earnings/by-symbols

   On cache miss or symbol-universe expansion, that request currently waits for
   a full FMP synchronization.

2. The frontend proxy currently aborts that request after roughly 15 seconds.

3. Upcoming Earnings is obtained from the explicit-symbol request, while Recent
   Earnings is obtained through a separate/global path.

4. Repeated tab switching or sorting can cause repeated requests while the
   underlying cache is still warming.

5. Ticker-detail latency/failure affects every ticker popup. EOSE is only a test
   symbol. A timeout must not be treated as proof that earnings/company data is
   absent.

A. Preserve the existing by-symbols contract for other consumers

Do NOT globally change the existing endpoint from synchronous to asynchronous
without preserving backward compatibility.

Extend the existing EarningsBySymbolsRequest with one optional additive field,
for example:

    wait_for_sync: bool = True

or an equivalently clear name.

Requirements:

- Default must preserve current synchronous behavior.
- Existing callers that omit the field must behave exactly as before.
- The Watchlist frontend will explicitly send wait_for_sync=false.
- Do not create a new endpoint.

When wait_for_sync=false, call the existing canonical function using:

- sync_on_miss=False
- background_sync_on_miss=True

Behavior:

- Full cache hit:
  return immediately with current events.

- Partial cache hit:
  return matching cached events immediately and schedule one background universe
  expansion.

- Stale cache with usable events:
  return matching stale events immediately and schedule one background refresh.

- True cold miss:
  return immediately with cache_status=miss_syncing and start the existing
  background synchronization.

No provider call may block the non-waiting request path.
