────────────────────────────────────────────────────────────────────

This is the central performance requirement.

BACKGROUND jobs should not call a blocking limiter acquire when there is
insufficient provider headroom.

A background scan should behave as:

logical scheduler wakes
        ↓

    yes → use cache, zero provider calls
        ↓

        ↓
lane has capacity AND global background capacity exists while preserving
interactive reserve?
    yes → make provider call
    no  → defer this physical refresh and use existing cache/LKG/null contract
          exactly as the caller already supports
        ↓
next existing scheduler cycle gets another opportunity

Do NOT create a separate retry queue.

Do NOT create hundreds of sleeping tasks.

Do NOT delay the next logical scheduler cadence.
