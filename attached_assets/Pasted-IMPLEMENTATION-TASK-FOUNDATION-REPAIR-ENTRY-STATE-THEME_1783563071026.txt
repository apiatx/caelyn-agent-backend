PHASE 3 — STAGE ANALYSIS V2 REPAIR
==================================

The current stage_analysis.py has a known likely false-positive path:

price above rising 30-week MA
+
price_vs_ma > 20%
+
prior 26-week trend positive
→ Stage 3m

For high-beta growth stocks, strong Stage 2 breakouts can become >20% above the 30-week MA quickly and be incorrectly labeled Stage 3.

The core conceptual correction is:

STAGE and EXTENSION are different dimensions.

A ticker can be:

Stage 2 + Extended
Stage 2 + At Support
Stage 2 + Breakout Ready

Do not use extension alone to force Stage 3.

REQUIREMENTS:

1. Preserve the existing analyze_symbol_stage() public contract and existing LKG producer architecture.

2. Preserve existing legacy stage values/labels as much as possible for frontend compatibility.

3. Refactor the Stage 3m classification so that absolute `price_vs_ma > 20%` is NOT by itself sufficient to advance a strong rising Stage 2 stock into Stage 3m.

4. Before changing the rule, inspect currently available metrics in stage_analysis.py and existing cached daily/weekly bars.

Reuse existing data.

Do not create a new provider path.

5. Qualification for Stage 3 / Stage 3m should require evidence of maturation/deterioration beyond simple extension.

Use the strongest existing repo-grounded combination available from:

duration/weeks since breakout or sustained advance
30-week MA slope behavior
slope deceleration/flattening
recent higher-high/higher-low structure
distance from prior base/breakout
volatility-normalized extension if ATR or equivalent can be calculated locally from already-fetched bars
volume behavior
loss of momentum after sustained prior uptrend

Do not force every listed metric if the data path does not support it cleanly.

6. Add a separate deterministic extension state to the stage result.

At minimum:

extension_state:
NOT_EXTENDED
MODERATELY_EXTENDED
EXTENDED
EXTREME_EXTENSION

and numeric fields if safely derivable:

extension_pct_30w_ma
extension_atr

7. Stage must answer:

What structural Weinstein stage is the ticker in?

Extension must answer:

How stretched is price relative to that structure?

8. Preserve LKG degraded-run protection and retry behavior.

9. Add a comparison diagnostic that can show:

old_stage
new_stage
extension_state
reason

for currently cached ticker symbols.

Do not automatically rewrite historical records.

PHASE 4 — BUILD DETERMINISTIC ENTRY STATE ENGINE
================================================

Create a new backend service dedicated to entry timing.

Suggested path:

backend/services/entry_state_service.py

Use existing cached/fetched historical-price architecture already used by stage_analysis.py or another canonical technical service.

Do not create a new provider client.

Do not create direct frontend provider calls.

PRIMARY QUESTION:

Is this asset:

A. Before the main expansion?
B. In a constructive continuation/reset?
C. Already too late / exhausted?
D. Structurally broken or unclear?

The user's strategy prioritizes finding strong assets BEFORE the obvious move.

A stock that has already moved can still be actionable if:

* it is a strong fundamental/theme leader,
* or a material catalyst changed the story,
* and it is now in a controlled dip/retest/reset after the initial move.

The engine must distinguish these cases.

CORE INTENT:

EARLY_REVERSAL:
Previously weak/neutral theme begins showing improving short-term RS, positive acceleration, improving breadth and/or capital/social confirmation before long-window leadership is obvious.

EMERGING:
Positive multi-input improvement with growing participation.

ACCELERATING:
Already improving and rate of improvement is increasing.

LEADING:
Strong absolute/relative performance with broad confirmation.

EXTENDED:
Leading but short-term move is stretched; capital may still be present but entry risk is elevated.

DETERIORATING:
Previously leading/accelerating theme loses RS acceleration, breadth, flow, or participation.

LAGGING:
Weak relative state without credible reversal evidence.

Avoid a simplistic weighted formula that allows one extreme metric to dominate everything.

Use explicit state-transition logic and a normalized supporting score.
