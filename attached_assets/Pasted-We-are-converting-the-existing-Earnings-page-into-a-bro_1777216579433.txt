4. Implement these backend endpoints:

GET /api/catalysts/overview
Returns:
{
  "asOf": string,
  "tabs": {
    "earnings_dates": { "count": number, "events": [...] },
    "dividends": { "count": number, "events": [...] },
    "ipos": { "count": number, "events": [...] },
    "splits": { "count": number, "events": [...] },
    "economic_releases": { "count": number, "events": [...] },
    "treasury_macro": { "count": number, "events": [...] },
    "recent_earnings": { "count": number, "events": [...] },
    "sec_filings": { "count": number, "events": [...] },
    "analyst_ratings": { "count": number, "events": [...] },
    "insider_transactions": { "count": number, "events": [...] }
  },
  "summary": {
    "highImportanceCount": number,
    "watchlistCatalystsCount": number,
    "portfolioCatalystsCount": number,
    "nextMajorCatalysts": [...]
  },
  "status": "ok" | "partial" | "error",
  "errors": []
}

GET /api/catalysts/events
Query params:
- tab: earnings_dates | dividends | ipos | splits | economic_releases | treasury_macro | recent_earnings | sec_filings | analyst_ratings | insider_transactions | all
- from: YYYY-MM-DD
- to: YYYY-MM-DD
- symbols: comma-separated tickers, optional
- scope: all | watchlist | portfolio
- sector: optional
- marketCap: all | mega | large | mid | small | micro
- eventType: optional
- limit: default 100
- refresh: boolean default false

Returns:
{
  "asOf": string,
  "tab": string,
  "from": string,
  "to": string,
  "filters": {...},
  "events": [...],
  "count": number,
  "status": "ok" | "partial" | "error",
  "errors": []
}

GET /api/catalysts/filters
Returns available filter values:
{
  "sectors": [...],
  "marketCapBuckets": ["mega", "large", "mid", "small", "micro", "unknown"],
  "eventTypes": [...],
  "watchlistSymbols": [...],
  "portfolioSymbols": [...]
}

Optional but preferred:
GET /api/catalysts/by-symbol/{symbol}
Returns all recent and upcoming catalysts for one ticker. This can power the existing popup later without replacing it now.

7. Caching:
Implement caching aggressively because calendar data does not need second-by-second refresh.
Suggested TTLs:
- earnings_dates: 6 hours
- dividends: 12 hours
- IPO calendar: 12 hours
- stock splits: 12 hours
- economic releases: 6 hours
- treasury rates/macro: 3-6 hours
- recent earnings reports: 6 hours
- SEC filings: 1-3 hours
- analyst ratings: 6 hours
- insider transactions: 3-6 hours
- profile/reference enrichment: 24 hours

Use the existing cache layer if the repo has one. If not, use a small disk-backed cache or existing in-memory cache pattern with clear keys.

Cache key examples:
catalysts:v1:{tab}:{from}:{to}:{scope}:{symbols_hash}
catalysts:profile:v1:{symbol}
catalysts:filters:v1
