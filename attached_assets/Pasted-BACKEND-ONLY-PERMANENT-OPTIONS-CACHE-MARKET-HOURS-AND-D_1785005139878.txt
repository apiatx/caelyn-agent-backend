BACKEND ONLY — PERMANENT OPTIONS CACHE, MARKET-HOURS, AND DATA-UNIFICATION FIX

Work only in the backend repository.

Audit first, then implement the fix in this same task.

Do not touch the frontend.
Do not create a new parallel options scanner.
Do not create a competing options cache architecture.
Do not add request-time Tradier calls.
Do not change the current Options Score formula or scoring weights in this task.
Do not remove existing endpoints or response fields.
Preserve existing paths and repair the architecture in place.

GOALS

Fix these two related problems together:

1. Options data becomes incomplete or blank after normal market hours and over weekends.
2. The Watchlist Options view and Options Flow page expose different subsets of options data and may still trigger separate Tradier scans for the same ticker.

The final architecture must have:

* Tradier options scans only during the regular U.S. options session
* one canonical per-ticker options snapshot
* one durable last-known-good snapshot
* all pages reading the same cached snapshot
* zero duplicate Tradier chain scans caused by different pages
* full options field availability for Watchlist, Options Flow, Portfolio, ticker popup, and Confluence
* no scoring changes yet

* America/New_York timezone
* valid U.S. trading day
* normally 9:30 a.m.–4:00 p.m. ET
* actual early-close time on early-close days
* no scans on full market holidays
* no scans during premarket
* no scans during postmarket
* no scans overnight
* no scans on weekends

Reuse an existing canonical exchange-calendar helper if one exists.

PART 7 — SAFE PROMOTION AND MERGING
===================================

Separate:

1. working scan state
2. canonical last-known-good state

Do not replace the canonical snapshot after each partial batch.

Promote a new LKG only when:

* scan occurred during regular market hours
* scan completed successfully
* schema is valid
* expected universe is known
* coverage is reasonably consistent with the previous successful snapshot
* result is not suspiciously smaller
* provider failure level is acceptable
* meaningful options fields are present

Promotion must be atomic.

If validation fails, keep the previous LKG unchanged.

Per ticker, do not overwrite valid prior data with:

* null fields
* empty chains
* empty expirations caused by failure
* timeout
* rate-limit result
* scan_pending
* scan_in_progress
* optionable_pending_chain
* generic pending
* malformed response
* closed-market result
* sparse placeholder
* accidental zero-filled row

Only mark `confirmed_no_options` from a valid regular-session result with the existing safeguards.

PART 8 — FIX PARTIAL-CACHE SUPPRESSION
======================================

Audit all combined-cache accessors.

A small nonempty master cache must not suppress a much larger supplement, sectors, disk, or Neon LKG.

Correct behavior must be per ticker:

1. durable LKG provides the broad baseline
2. valid supplement/current rows overlay it
3. valid master/live rows overlay those
4. missing tickers retain their LKG rows
5. partial memory coverage never blocks durable fallback loading

Remove any global behavior equivalent to:

`if not combined: load the LKG`

The fallback decision must happen per symbol.
