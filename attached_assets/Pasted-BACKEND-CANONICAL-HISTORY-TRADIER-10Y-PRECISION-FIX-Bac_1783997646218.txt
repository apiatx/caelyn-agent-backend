BACKEND — CANONICAL HISTORY TRADIER 10Y PRECISION FIX

Backend only.

Do not touch frontend.
Do not change Confluence scoring.
Do not rewrite the Tradier limiter.
Do not touch Options Flow.
Do not remove the canonical history cache.
Do not remove safe-mode flags.
Do not run a full watchlist backfill yet.

Goal:

We need to align canonical history with the correct provider strategy.

Correct architecture:

- Tradier should be the primary candidate for 10Y / lifetime daily historical candles.
- FMP is secondary/fallback and should not be treated as the required 10Y upgrade path.
- Canonical history target is 10 years max.
- If ticker is younger than 10 years, cache all available history back to IPO/listing date.
- If ticker is older than 10 years, cap at 10 years because older data is not useful for the current Stage/Fib/Entry system.

Important:

The previous V4.2.5.4 report claimed Tradier caps at ~1,253 bars / ~5 years and that FMP is needed for 10Y.

Do not assume that is true.

Tradier documentation says historical daily pricing usually covers the entire lifetime of the company when reasonable start/end dates are supplied.

Therefore, first prove why the current implementation only returned ~5Y.

==================================================
PART 4 — FIX PROVIDER STRATEGY
==================================================

Provider order should be:

1. Fresh canonical cache
2. Tradier historical daily bars for up to 10Y/lifetime
3. FMP fallback only if Tradier fails, returns unusable data, or a symbol-specific issue is detected
4. Existing 400-bar Stage cache as emergency fallback only

Do not use FMP as the default “10Y upgrade” path if Tradier can return 10Y.

If Tradier returns only 5Y for a symbol despite correct 10Y request:

- mark provider result precisely
- do not call it available_10y
- do not call it actual_ticker_history_limit unless ticker is genuinely younger than 10Y
- optionally mark needs_provider_verification or needs_fmp_fallback

==================================================
PART 5 — FIX STATUS TAXONOMY
==================================================

Canonical history statuses should represent the truth:

available_10y
available_lifetime_under_10y
available_5y_partial_long_history
available_3y_partial_history
partial_history
intermediate_only
recent_only
actual_ticker_history_limit
provider_cap_detected
provider_failed
not_yet_backfilled
cache_corrupt_needs_rebuild

Rules:

available_10y:
- >= 2200 bars OR clearly covers ~10 calendar years

available_lifetime_under_10y:
- ticker is younger than 10Y
- cached bars cover actual public trading history
- examples may include CRDO, WYFI, SOFI, HOOD depending listing history

available_5y_partial_long_history:
- ~1100–2199 bars
- symbol appears older than 5Y
- this is not complete for 10Y target

provider_cap_detected:
- correct 10Y request was sent
- provider returned only capped range
- symbol is known older than returned range

actual_ticker_history_limit:
- no older bars exist because ticker is genuinely newer

Do not classify a known older ticker as actual_ticker_history_limit just because Tradier returned 5Y.

==================================================
PART 6 — PARTIAL HISTORY MUST STILL BE USED
==================================================

Do not discard usable canonical history.

Rules:

- available_10y: use always
- available_lifetime_under_10y: use always
- actual_ticker_history_limit: use always
- available_5y_partial_long_history: use always
- available_3y_partial_history: use always
- partial_history >=504 bars: use always, but mark limitation
- intermediate_only >=252 bars: use always for recent/intermediate analysis, but mark limitation
- only return None if cache is corrupt, empty, or below minimum usable bars

Stage/Entry/Fib should use the best available canonical bars, not fall back to 400 when a better partial cache exists.

==================================================
PART 7 — 10Y BACKFILL POLICY
==================================================

Full 10Y historical fetch should only happen when:

- admin endpoint explicitly requests mode=initial_full_backfill or manual_rebuild
- CANONICAL_HISTORY_BACKFILL_ENABLED=true
- CANONICAL_HISTORY_FULL_BACKFILL_ENABLED=true
- market is closed unless explicitly forced
- provider call goes through scheduler
- no raw httpx bypass

Target:

canonical_history_target_years = 10
canonical_history_requested_days = 3650
preferred_bars = approximately 2520 trading bars
minimum_10y_bars = 2200

After a symbol reaches available_10y or available_lifetime_under_10y:
- do not full-refetch on normal runs
- do not full-refetch because TTL is stale
- mark it complete
