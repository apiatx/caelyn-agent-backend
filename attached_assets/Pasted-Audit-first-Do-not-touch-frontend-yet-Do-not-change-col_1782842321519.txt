Part C — Earnings Date correctness

`Earn. Date` should mean next/upcoming earnings date.

Audit the source currently used by the fundamentals overlay:

* symbol earnings endpoint?
* earnings calendar date-range endpoint?
* cached Calendar page data?
* CSV fallback?

Problem:
If FMP returns no future earnings date, the current no-null-overwrite behavior may preserve an old CSV date. That makes the UI show past dates, which is misleading.

Fix rule for `Earn. Date` only:

* If FMP provides a future/upcoming earnings date, use it.
* If FMP provides no future/upcoming earnings date:

  * do not overwrite with fiscal quarter-end dates
  * do not show a stale CSV date if it is before today
  * if CSV date is future, it may be used as fallback
  * if CSV date is past, final value should be blank/`—` or marked missing, not shown as next earnings

Do not apply this stricter stale-date rule to every field.
This is specifically for `Earn. Date`.

Use timezone-aware current date, preferably America/New_York.
