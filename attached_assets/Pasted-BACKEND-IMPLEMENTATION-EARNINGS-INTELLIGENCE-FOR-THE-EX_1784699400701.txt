Revenue surprise:

(actual - estimate) / abs(estimate) * 100

(actual - estimate) / abs(estimate) * 100

PART 5 — FISCAL-PERIOD JOINING

The /stable/earnings response lacks fiscal period and fiscal year.

Join earnings events to quarterly income-statement rows carefully.

Preferred matching order:

1. Exact match on earnings date and filingDate where valid
2. Exact match on earnings date and date/report date where available
3. Closest plausible filing row within a small documented date tolerance
4. Otherwise fiscal_year and fiscal_period remain null

Do not attach the wrong quarter merely to avoid a null.

Store join_method and join_confidence when helpful for auditing.

PART 8 — REACTION CALCULATION

Use actual ordered trading sessions, never calendar-day arithmetic.

For confirmed or sufficiently inferred AMC:

- baseline = report-date regular-session close
- reaction session 1 = next trading session
- opening_gap_pct = T+1 open versus baseline
- reaction_1d_pct = T+1 close versus baseline
- reaction_3d_pct = third subsequent trading-session close versus baseline
- reaction_5d_pct = fifth subsequent trading-session close versus baseline

For confirmed or sufficiently inferred BMO:

- baseline = prior trading-session close
- reaction session 1 = report-date trading session
- opening_gap_pct = report-date open versus baseline
- reaction_1d_pct = report-date close versus baseline
- reaction_3d_pct = third applicable reaction-session close versus baseline
- reaction_5d_pct = fifth applicable reaction-session close versus baseline

For timing_confidence = inferred_low or timing = unknown:

- do not present the result as an exact BMO/AMC reaction
- either return reaction fields as null, or
- calculate a clearly labeled close_to_close_approximation

Recommended behavior:

- unknown timing: calculate date-close to next-session-close only as calculation_method = unknown_timing_close_to_close
- exclude this approximation from BMO/AMC-specific summary statistics
- do not calculate an opening gap unless the baseline session is unambiguous

For each event return:

- baseline_date
- baseline_close
- first_reaction_session
- opening_gap_pct
- reaction_1d_pct
- reaction_3d_pct
- reaction_5d_pct
- max_upside_5d_pct
- max_drawdown_5d_pct
- sessions_used
- calculation_method
- calculation_confidence
- reactions_final
- bars_source

max_upside_5d_pct:

- use the highest intraday high in the applicable five-session reaction window versus baseline

max_drawdown_5d_pct:

- use the lowest intraday low in that window versus baseline
- express downside as a negative percentage
- if price never trades below baseline, return 0.0 rather than a positive “drawdown”

If fewer than five reaction sessions have elapsed:

- calculate only available horizons
- leave unavailable horizons null
- reactions_final = false

Once T+5 has completed:

- reactions_final = true
- avoid unnecessary recomputation unless historical bars were corrected
