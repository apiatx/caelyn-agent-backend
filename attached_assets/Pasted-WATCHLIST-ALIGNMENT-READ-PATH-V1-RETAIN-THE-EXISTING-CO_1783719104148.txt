WATCHLIST ALIGNMENT READ PATH V1 — RETAIN THE EXISTING CONFLUENCE PRODUCER OUTPUT AND ADD A COMPACT FULL-WATCHLIST ALIGNMENT ENDPOINT

Work only in the existing backend Replit project.

The backend scoring/model stack is complete for the current phase.

A serving-path audit has proven:

1. `build_confluence_snapshot()` has exactly two effective serving paths today:

   * GET `/api/alpha/confluence`
   * `get_confluence_for_symbol()` → GET `/api/alpha/confluence/{symbol}`

2. There is currently:

   * no retained Confluence snapshot
   * no Confluence LKG
   * no Neon Confluence table
   * no background Confluence warmer
   * no Confluence scheduler

3. GET `/api/alpha/confluence`:

   * synchronously builds the full current Stage2/Confluence universe
   * currently ~379 symbols
   * takes approximately 70–80 seconds on the measured full build
   * then hard-caps the returned result list to 200 rows
   * therefore cannot safely serve the current ~375-ticker Watchlist Alignment UI

4. `get_confluence_for_symbol()` is appropriate for individual detail lookup but must NOT be looped across the full Watchlist because each call reloads the same shared upstream inputs.

5. `build_confluence_snapshot()` is the canonical existing producer and is pure over existing cache/LKG/Neon reads. It adds no provider calls.

The chosen architecture is:

PART 4 — STALE-WHILE-REVALIDATE SEMANTICS
=========================================

The Watchlist UI must not block for ~79 seconds every time an upstream fingerprint changes.

Implement these exact serving semantics:

A. Retained snapshot exists
AND
current source fingerprint == retained source fingerprint

→ return retained snapshot immediately

B. Retained snapshot exists
AND
fingerprint changed

→ return retained snapshot immediately

→ trigger ONE asynchronous/background rebuild using the EXISTING `build_confluence_snapshot()` producer

→ when the build completes successfully:
atomically replace retained snapshot
update built_at
update source_fingerprint

C. No retained snapshot exists

→ perform one cold build using the existing producer

→ retain the completed snapshot

→ return it

The cold-start path may be slow once.

Steady-state Watchlist page loads must not synchronously rebuild the full Confluence universe.

Do not silently return an empty result while the first build runs.
