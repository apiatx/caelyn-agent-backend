FastAPI Agent Instructions
Problem: The POST /api/portfolio/upload-csv endpoint (with mode="import") is not correctly processing sell transactions. It imports all buy lots as open holdings but ignores sells, so fully-closed positions remain in the open holdings list and no closed trade records are created.

Also observed: Some holdings have duplicate lots (same ticker, same date, same shares appearing twice — e.g. SIVEF has a 4000-share lot on 2026-04-09 duplicated). The import appears to be adding lots multiple times.

Fix 1 — CSV Import: Net buys vs sells per ticker
When processing a CSV import, for each ticker:

Collect all transactions — separate into BUY rows and SELL rows (check Transaction Type / Action column, normalize to uppercase, accept: Buy, Sell, Sell Short, Reinvest Shares, etc.)

Calculate net open shares:

total_bought = sum of all Buy shares for this ticker
total_sold   = sum of all Sell shares for this ticker
net_shares   = total_bought - total_sold

Weighted avg buy cost:

avg_entry_price = sum(buy_shares[i] × buy_price[i]) / total_bought

Weighted avg sell price:

avg_exit_price = sum(sell_shares[i] × sell_price[i]) / total_sold  (if total_sold > 0)

Apply the results:

If net_shares > 0 (position still open): upsert holding with ticker, net_shares, avg_cost = avg_entry_price, entry_date = earliest buy date. Do not add the same lots twice — use a dedup check (date + shares + price) before appending.

If net_shares == 0 (fully closed): delete the holding for this ticker (if it exists), create a closed trade record (see schema below).

If 0 < net_shares < total_bought (partially closed): update holding shares to net_shares, update avg_cost to reflect remaining lots (FIFO), create a partial closed trade record for the sold portion.

Fix 2 — Create closed trade records
