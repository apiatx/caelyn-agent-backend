Backend Replit instructions — separate representative ETF chart symbol from true theme holdings

New issue:
The Themes page expanded view is showing ETF holdings from the representative chart ticker. Example: Substrates / Packaging uses SOXX as representative_symbol for the TradingView chart, but when expanded it shows SOXX holdings like AVGO, MU, AMD, NVDA, INTC. That is wrong.

Important distinction:
representative_symbol is for the TradingView chart only.
It must not define the theme’s holdings/basket.
It must not control the expanded holdings table.
It must not replace the true theme basket.

The true theme basket should be the actual tracked symbols for that theme:

* existing custom basket symbols
* existing manually curated theme symbols
* watchlist-added symbols mapped to that canonical theme
* existing ETF/manual tracker symbols only when they are actually intended to be part of the theme basket/performance basket

Audit first:

1. Find the endpoint/data source used by the expanded Themes page holdings table.
2. Find where ETF holdings are fetched or attached.
3. Find whether the expanded view uses representative_symbol, lead_proxy, ticker, or proxy_symbols to decide which holdings to show.
4. Confirm why Substrates / Packaging expands to SOXX holdings instead of AMKR/ASX.
5. Identify all custom/hybrid/watchlist-enriched themes that currently show representative ETF holdings incorrectly.

Required backend behavior:
Add an explicit distinction between:

1. representative_symbol

   * one ETF/proxy used for TradingView chart only

2. performance_symbols

   * the merged basket used for 1D/7D/30D/YTD/1Y/5Y performance calculations

3. display_symbols or theme_holdings

   * the true symbols shown in the expanded theme holdings table

4. holdings_display_mode

   * "theme_basket" for custom/hybrid/watchlist-enriched themes
   * "etf_holdings" only for themes where the ETF holdings are intentionally the actual theme representation
   * optional "none" if no holdings should be shown

Rules:

1. For custom themes, expanded holdings must show the theme basket, not representative ETF holdings.
2. For hybrid/watchlist-enriched themes, expanded holdings must show the merged theme basket, not representative ETF holdings.
3. For pure ETF themes, it is okay to show ETF holdings only if that was already intended.
4. representative_symbol should remain available for the chart.
5. representative_symbol should not be used to fetch/choose expanded holdings unless holdings_display_mode = "etf_holdings".
6. Do not remove watchlist tickers from performance.
7. Do not change Watchlist page behavior.
8. Do not create new LLM calls.
9. Do not create new frontend-only classification logic.
