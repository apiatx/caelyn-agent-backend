Phase 4A plan is approved with one correction before implementation.

The active quote-demand registry concept is aligned:

* quote-only priority
* no options priority
* no new scheduler
* no endpoint response shape changes
* no new quote cache namespace
* no raised Tradier RPM
* demand registration as a side effect of existing page endpoints
* active demand merges by symbol/scope
* all pages still read the canonical quote cache/LKG

Correction required:
Sorting `remaining` by demand priority is necessary but may not be sufficient if `_tradier_batch()` launches all chunks concurrently with `asyncio.gather`.

If chunks are launched concurrently, chunk 0 is not guaranteed to consume quote budget before chunk 1/2/3. Under quote-lane budget pressure, lower-priority chunks could still race ahead and consume budget.

Implementation requirement:
Make quote batch fetching priority-aware.

Minimum acceptable behavior:

1. `get_realtime_quotes()` sorts cache-miss symbols by demand priority desc.
2. `_tradier_batch()` must process the highest-priority chunk first.
3. If multiple chunks are needed, lower-priority chunks should not be allowed to race ahead of higher-priority chunks under budget pressure.
4. Keep concurrency only where it does not break priority ordering.
5. No new scheduler is needed.

Possible simple implementation:

* split sorted symbols into chunks
* await the first/highest-priority chunk first
* then process remaining chunks sequentially or with limited concurrency
* preserve existing cache writes and response shape
* if quote lane is saturated, high-priority symbols should be the ones most likely to have been fetched before deferral

Proceed with Phase 4A implementation only after applying that correction.
