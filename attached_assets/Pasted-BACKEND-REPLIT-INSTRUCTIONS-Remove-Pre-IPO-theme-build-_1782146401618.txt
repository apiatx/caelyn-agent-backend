Task 2 — Net Options Flow aggregation

Goal:
Create a cached backend endpoint that powers a new Options Flow page tab called “Sectors”.

This endpoint should show:

1. Sector-level net options flow.
2. Click sector → themes in that sector.
3. Click theme → tickers in that theme.
4. Each level should include:

   * call premium dollars
   * put premium dollars
   * net premium dollars
   * net bias: bullish / bearish / neutral
   * put/call ratio
   * ticker count / contributing ticker count
   * updated_at / data freshness

Definitions:
Audit existing Options Flow data first. Use existing fields if they already exist.

Preferred money-flow formula:

* call_premium_total = sum call option premium dollars
* put_premium_total = sum put option premium dollars
* raw_net_call_minus_put = call_premium_total - put_premium_total

If existing flow data includes buy/sell side/aggressor:

* bullish_premium = bought calls + sold puts
* bearish_premium = bought puts + sold calls
* signed_net_flow = bullish_premium - bearish_premium

If side/aggressor is unavailable or unreliable:

* use raw_net_call_minus_put
* expose `net_flow_method = "call_minus_put_premium"`

For put/call ratio:

* money_put_call_ratio = put_premium_total / call_premium_total where call_premium_total > 0
* also expose average_ticker_put_call_ratio if existing ticker-level PCR is already calculated
* do not use contract count PCR if premium-dollar PCR is available, unless clearly named

Important:
Do not just show put/call ratio. We need dollar flow:

* calls dollars
* puts dollars
* net dollars
* net direction

Theme membership:
Use the curated Themes page universe:

* theme_id
* display_name
* classification
* theme_holdings / performance_symbols
* manual admin additions/removals
* pre_ipo removed

Do not read live Watchlist categories for this feature. The Themes universe is already frozen/curated.

Many-to-many rule:
A ticker can belong to multiple themes.

Theme aggregation:

* If ticker belongs to multiple themes, it contributes to each theme it belongs to.

Sector aggregation:
Avoid accidental double-counting inside a sector.
Recommended rule:

* sector totals should be computed from unique tickers in that sector.
* if a ticker appears in multiple themes inside the same sector, count it once at sector level.
* theme totals can still include the ticker in each theme.
* expose `sector_total_method = "unique_ticker_sum"` so the frontend understands sector totals may not equal sum of visible theme cards when overlaps exist.
