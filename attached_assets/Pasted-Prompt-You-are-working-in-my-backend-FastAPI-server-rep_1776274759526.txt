Factor definitions
1. supply_chain_confirmation

Goal:

confirm that a name is not just thematically related, but actually sits in a believable supply chain / customer / component position

Use existing sources if available:

Finnhub supply chain / company profile / industry metadata
news text
company description
existing theme/bottleneck maps
manually curated supplier/customer associations where needed

Scoring:

high if direct supplier or tightly linked component provider
medium if adjacent beneficiary
low/neutral if vague theme-only exposure

Return metadata:

matched supply-chain tags
confirmation reason(s)
source type (manual_map, profile_keyword, news_inference, etc.)
2. ebitda_inflection_proximity

Goal:

support S&J-style rerating logic around near-positive EBITDA/FCF turns

Use existing sources if available:

financial statements
margins
operating income / EBITDA trend
earnings estimate fields if present
sequential and YoY improvement trends

Scoring:

high if the business appears near a credible inflection
medium if trending toward improvement
low if deteriorating badly or nowhere near

If direct EBITDA data is sparse, use a clear documented heuristic.

3. backlog_quality

Goal:

reward companies where backlog/order book/capacity reservations appear real and relevant

Use:

news scan
company descriptions
filings/news keywords like backlog, bookings, orders, reservations, awarded contract, purchase commitment
sector-specific heuristics if necessary

Scoring:

high if backlog/order signals are recent and meaningful
medium if present but weak/older/unclear
low/neutral if absent
4. evidence_freshness

Goal:

distinguish stale thesis support from recent validating evidence

Use:

recency of recent news
recency of filings
recency of earnings
recency of theme-confirming events

Scoring:

fresh confirmation in last 7–21 days = high
aging evidence = medium
stale/no recent confirmation = low

This factor should help both playbooks stay current.

5. execution_risk

Goal:

penalize names where the business/story is fragile operationally

Use:

weak margins
deteriorating revenue trend
high debt stress
repeated financing need
volatile narrative unsupported by business progress
small-cap fragility heuristics

Scoring:

higher score should mean higher risk if using penalties
keep consistent with your existing penalty design

Return reasons.

6. insider_buying

Goal:

reward meaningful insider buying signals if available

Use:

any existing insider transaction source in repo
fallback news keyword scan
if no real data exists, implement a documented heuristic or leave neutral gracefully

This does not need to be perfect, but should exist as a real factor path if possible.

7. policy_tailwind

Goal:

capture names that benefit from policy/regulatory/onshoring/defense/AI infrastructure tailwinds

Use:

theme map
sector tags
keyword inference from descriptions/news
existing macro/theme logic if available

Examples:

defense optics
energy infrastructure
grid equipment
onshoring/industrial policy
AI capex buildout beneficiaries

Scoring:

high where policy/macro tailwind clearly aligns
medium where indirect
low otherwise

Part 3 — Add a dedicated strategy-aware terminal endpoint

This is the key terminal integration step.

Create a new isolated route like:

POST /api/playbooks/analyze

Do not touch /api/query.

Purpose

This route powers the AI Terminal when the user explicitly selects:

Serenity
S&J
Default mode in frontend will continue to use /api/query.
Non-default strategy modes will call this new route.
Request shape

Support a request body like:

{
  "playbook_id": "serenity",
  "query": "Analyze my watchlist for the best asymmetric bottleneck setup",
  "context_mode": "watchlist",
  "tickers": ["NBIS", "AAOI", "LITE", "AMPX"],
  "holdings": [],
  "limit": 10,
  "include_breakdown": true
}

Support at least these fields:

playbook_id
query
context_mode (watchlist, portfolio, custom, universe)
tickers
holdings
universe
limit
include_breakdown

Be forgiving and validate cleanly.

Endpoint behavior
For context_mode = watchlist
score provided tickers with selected playbook
rank top ideas
summarize best fits
summarize weak fits
return concise playbook-aware answer
For context_mode = portfolio
score holdings
return aggregate alignment
strongest aligned holdings
weakest aligned holdings
concise strategy-aware answer
For context_mode = custom
use supplied tickers
score + summarize
For context_mode = universe
use supported universe scan like ai_infra, defense, etc.
return top ideas
Response shape

Return something like:

{
  "playbook_id": "serenity",
  "playbook_name": "Serenity",
  "query": "Analyze my watchlist for the best asymmetric bottleneck setup",
  "answer": "Based on the Serenity playbook, the strongest bottleneck-aligned setups are NBIS and LITE...",

    {
      "ticker": "NBIS",
      "final_score": 82.1,
      "thesis_summary": "...",
      "fit_reasoning": ["...", "..."]
    }
  ],
  "rejected_or_low_fit": [
    {
      "ticker": "XYZ",
      "final_score": 41.2,
      "non_fit_reasoning": ["..."]
    }
  ],
  "portfolio_summary": null,
  "playbook_context": {
    "preferred_themes": ["neocloud", "photonics_cpo"],
    "positioning_style": "..."
  }
}

Keep this structured and terminal-friendly.

Answer generation rules

Do not call the main general AI brain here.

Build the response deterministically from:

ranking results

If you want a light summarization helper inside playbook service, that’s fine, but keep it isolated and deterministic. No coupling to /api/query.

Tone:
