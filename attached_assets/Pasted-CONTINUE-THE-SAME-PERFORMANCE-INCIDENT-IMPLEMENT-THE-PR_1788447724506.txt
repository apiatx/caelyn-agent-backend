PROVEN REGRESSION
=================

Commit:

f0b41157034aa39976a7480333fd7ec52a29ab89
"Bound Watchlist detail latency"

changed GET /api/watchlist/{watchlist_id} so that every request:

1. creates a worker for load_watchlist(watchlist_id)
2. waits on that canonical read
3. only AFTER the read completes or times out checks/serves _BULK_LKG
4. shields the load task, so timed-out reads continue running

This was intended to bound DB latency but under shared executor/resource contention it
does the opposite:

- an already-complete cached response cannot return immediately
- every browser request starts another unnecessary canonical read
- timed-out reads continue consuming worker/DB resources
- repeated requests can accumulate overlapping reads
- the latency of cached responses becomes coupled to unrelated background resource pressure

This is classified as:
