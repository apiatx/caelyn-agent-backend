## Issue 1 — Cash Runway must be recomputed after Cash carry-forward

Current problem:

The balance-sheet carry group contains:

* Cash
* Net Cash / Debt
* Cash Runway Months
* Cash Runway Status
* Cash-runway reason

When the balance-sheet endpoint fails, the old Cash Runway result is carried directly.

This is incorrect because current TTM FCF may have changed.

Example:

* Prior snapshot FCF positive → `self_funding`
* Current FCF negative
* Current balance-sheet request fails
* Old `self_funding` status must not survive

Fix:

1. Remove all Cash Runway fields and reasons from `_BS_CARRY_FIELDS`.
2. Carry only the balance-sheet inputs that remain valid during a transient failure:

   * `Cash`
   * `Net Cash / Debt`
3. Perform source-aware carry-forward.
4. After carry-forward is complete, recalculate Cash Runway using:

   * Effective current/carried Cash
   * Current refresh’s strict TTM Free Cash Flow
   * Current sector and industry
5. Clear old runway fields and reasons before writing the newly calculated result.
6. If current FCF is missing, do not blindly preserve an old runway classification unless explicit stale metadata is supplied.

Prove these transitions:

* old self-funding → current negative FCF + BS failure
* old 18 months → current positive FCF + BS failure
* old financial-sector N/M → current non-financial classification
* old numeric runway → current Cash unavailable and FCF available

## Issue 2 — Preserve HTTP/result-state information from FMP calls

Current `_get()` collapses all of these into `[]`:

* HTTP 200 with empty payload
* HTTP 402
* HTTP 403
* HTTP 404
* HTTP 429
* HTTP 500
* Timeout
* Connection error
* Invalid JSON

That prevents correct source-aware carry-forward.

Refactor `_get()` or add a compatible result wrapper so optional Quality endpoint callers can distinguish:

* `success_with_data`
* `success_no_data`
* `not_entitled`
* `transient_failure`

Classification:

* HTTP 200 + populated payload → `success_with_data`
* HTTP 200 + valid empty payload → `success_no_data`
* HTTP 402 or 403 → `not_entitled`
* HTTP 404 for a symbol-specific unsupported result → `success_no_data` unless the endpoint itself is invalid
* HTTP 429, 5xx, timeout, connection error or invalid response → `transient_failure`

Do not break the seven existing endpoint consumers.

A backward-compatible helper may be added for the three optional Quality endpoints if changing `_get()` globally is risky.

Carry-forward rules:

* `transient_failure` → prior source fields may be carried
* `success_no_data` → do not preserve obsolete numeric values; expose missing reason
* `not_entitled` → do not preserve obsolete numeric values; expose entitlement reason
* `success_with_data` → use only current results

Apply this to:

* Balance sheet
* Annual analyst estimates
* Financial scores

Test Financial Scores returning HTTP 200 with an empty list and prove that an old Altman Z score is not retained forever.
