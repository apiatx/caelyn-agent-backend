PRIMARY GOAL
Transition from the current multi-pipeline category-specific Options Flow architecture into a **single master unusual-options screener architecture** that:

1. scans broadly for unusual options signals across the market
2. ranks globally by abnormality/signal quality
3. tags each result with:

   * asset_type (stock / ETF)
   * market_cap_bucket (megacap / large / small / unknown)
4. preserves existing deep per-ticker detail/drilldown capability
5. feeds both:

   * the main Options page
   * the Home page Unusual Options Flow section

This should reduce backend complexity, improve speed, improve candidate breadth, and stop the current 4-tab orchestration from being the primary truth source.

TARGET ARCHITECTURE

PART 1 — Single Master Screener Snapshot
Create one master unusual-options screener snapshot as the primary truth source.

This master snapshot should:

* rank unusual options names globally
* include both stocks and ETFs
* include market-cap bucket tags for stocks
* preserve enough metadata for filtering/grouping later

Each row should include, at minimum:

* symbol
* asset_type (stock / ETF)
* market_cap_bucket (megacap / large / small / unknown)
* composite_score / unusual_score
* volume_vs_oi or vol_oi_ratio if available
* net_flow / premium / put_call_skew / strongest existing flow metrics
* price_change_pct if already available
* short signal_label / rationale
* updated_at or snapshot timestamp
* source metadata if useful

Important:

* “unusual” must remain abnormality-first, not size-first
* smaller names with truly abnormal flow should surface
* megacaps should not dominate by raw premium alone

PART 2 — Two-stage scanner architecture
Refactor the engine toward one master scanner with:

Stage 1: broad cheap candidate sweep

* broad universe
* cheaper signals
* maximize breadth
* minimize per-symbol cost

Stage 2: deep inspect finalists only

* apply richer chain/detail scoring only to shortlisted names
* produce final ranked leaderboard

This master screener should be the truth source for:

* main Options page
* Home page unusual options block

PART 3 — Filters, not separate truth pipelines
Do NOT make ETFs / Megacaps / Large / Small separate primary pipelines anymore.

Instead:

* maintain one master ranked snapshot
* attach category tags
* allow downstream views to filter:

  * ETFs
  * stocks
  * megacap
  * large
  * small

If you need transitional compatibility, you may still expose derived category slices, but they should come from the master snapshot where practical rather than from four fully separate long-running truth pipelines.

PART 4 — Preserve detail/drilldown compatibility
This is critical.

Do NOT break:

* ticker detail modal/popup support
* deeper options detail views
* chart-related backend support
* contract detail support
* existing per-ticker richer data fetch path

Required approach:

* keep existing detail endpoints/builders if they already work
* make screener rows link/resolve cleanly into those existing detail paths
* if any payload shape must change, keep backward compatibility or provide a clean adapter layer

The screener and the detail view are different jobs:

* screener = fast ranking
* detail = deep drilldown on click

Do not destroy the detail layer in the name of simplification.

PART 5 — Snapshot persistence and revisit behavior
Preserve and improve the new stale/LKG behavior:

* disk-backed validated last-known-good snapshot
* immediate stale-but-available on revisit/restart
* background refresh
* explicit metadata states:

  * live_ok
  * stale_but_available
  * refresh_in_progress
  * true_zero_results
  * no_data_yet

The main Options page should be able to show the best available snapshot immediately.
