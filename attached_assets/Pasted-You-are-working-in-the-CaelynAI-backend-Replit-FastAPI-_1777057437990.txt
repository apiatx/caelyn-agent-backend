You are working in the CaelynAI backend Replit FastAPI server.

Goal:
Add a new Portfolio Intelligence feature called “Compare to Watchlist” for the Portfolio page.

This should compare the user’s current saved/uploaded portfolio holdings against one selected saved watchlist from the Watchlist page and return a deeply structured, dated, cached AI report that answers:

1. How does the current portfolio stack up RIGHT NOW?
2. Which holdings are weaker than watchlist alternatives?
3. What would the agent replace, and why?
4. Which names should be kept, upgraded, trimmed, avoided, or monitored?
5. How does this change based on current market regime, thematic rotation, fundamentals, technicals, filings, news, catalysts, sentiment, and risk?

Important:
This must be a MANUAL expensive action. Do not run this automatically in the background. Do not refresh it on every page load. The report must persist after refresh/republish/page navigation so the frontend can show the last saved report with a generated timestamp.

Architecture requirements:
- Backend owns all expensive intelligence, data fetching, AI synthesis, caching, persistence, and refresh logic.
- Frontend should only call backend endpoints.
- Do not make the frontend assemble AI prompts or call model providers directly.
- Reuse existing portfolio/watchlist storage and auth/user identification patterns.
- Do not break existing Portfolio or Watchlist features.
- Audit existing Portfolio and Watchlist routes/models before changing anything.

- Return the full structured report.
- Include generated_at.
- Include data freshness metadata.
- Include API source metadata.

  - Report older than 24 hours.

- Even if stale, frontend should be able to display it with a stale badge and a refresh button.

Data pipeline:
Build a batch-first enrichment function, not one-off calls per ticker where avoidable.

Function suggestion:
build_portfolio_watchlist_comparison(user_id, watchlist_id, force_refresh=False)

Steps:
1. Load current portfolio holdings.
2. Load selected watchlist.
3. Normalize tickers:
   - uppercase
   - dedupe
   - remove invalid/empty symbols
   - preserve asset type if available
4. Create universe:
   - portfolio tickers
   - watchlist tickers
   - mark each ticker as portfolio_only, watchlist_only, or both
5. Fetch data with strict provider priority and rate protection.
6. Score each ticker.
7. Build replacement recommendations.
8. Ask AI synthesis layer for final structured report.
9. Persist result.
10. Return result.

Provider priority / API budget:
Use the following source strategy:

Primary:
- FMP for broad fundamentals, profile, key metrics, financials, ratios, enterprise value, revenue growth, margins, FCF, debt, valuation, analyst/earnings basics if available.
- Tradier for current/near-real-time quotes and price action where available.
- SEC EDGAR for filings, recent 10-K/10-Q/8-K, risk factors, material events, and filing recency.
- Existing internal market regime / sector rotation / macro endpoints if they already exist.
- Existing options flow / Tradier data only when useful, not mandatory for every ticker.

Use sparingly:
- Finnhub for company news, filings sentiment, recommendation trends, price target, earnings calendar, surprise history, and profile gaps.
- Alpha Vantage only as a last-resort technical/fundamental fallback because it has very low daily limits.
- Polygon only if you already have a cheap batch/aggregate path available; respect 5 calls/minute.
- Finviz scraper for technical setup/snapshot only, with throttling and weekend handling. Do not rely on Finviz on weekends.

- OpenAI can orchestrate and structure the comparison if that is the existing system pattern.

- Gemini can be used for grounded web/regime/thematic research if already wired.
- DeepSeek can be used for cheap intermediate summarization if needed.

Do not blindly call every AI model every time. Use a model budget switch:
- normal mode: fundamentals + quotes + internal regime + limited news + final Claude synthesis
