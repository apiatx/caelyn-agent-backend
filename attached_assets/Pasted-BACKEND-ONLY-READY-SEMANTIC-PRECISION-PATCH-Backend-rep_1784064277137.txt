==================================================
PART 2 — REFINE READY PROMOTION FOR WAIT_FOR_RETEST
==================================================

Do not automatically promote every P6 ACTIONABLE_NOW row to READY.

Before promoting to READY, check whether it is actually executable now.

For rows with entry_state == "WAIT_FOR_RETEST":

Use active_support_status and distance_to_active_support_pct.

Rules:

A. If active_support_status in:
- bounced_from_support
- testing_support
- near_major_support
- retest_in_progress

OR distance_to_active_support_pct <= 5:

Then:
- keep/promote READY
- execution_state = RETEST_IN_PROGRESS
- is_actionable_setup = true

B. If distance_to_active_support_pct > 5 and <= 15:

Then:
- do NOT mark is_actionable_setup true
- actionability should be WAIT_FOR_RETEST
- bucket can remain NEAR_ACTIONABLE or WAIT_FOR_RETEST if supported
- execution_state = SET_ALERT_FOR_RETEST
- why_wait should include "Entry trigger not reached yet"

C. If distance_to_active_support_pct > 15:

Then:
- do NOT mark READY
- actionability = WAIT_FOR_RETEST
- is_actionable_setup = false
- execution_state = WAIT_FOR_RETEST
- why_wait should include "Price is still far above retest/support zone"

D. If distance is missing:

Be conservative:
- only allow READY if support status clearly says bounced/testing/near support
- otherwise SET_ALERT_FOR_RETEST

Important:

A high-quality setup that is 20–50% above its retest level is not Ready Now. It belongs in Wait for Retest / Set Alert.

PART 4 — EXTREME EXTENSION SEVERITY CLEANUP
==================================================

Current READY rows can have EXTREME_EXTENSION when extension_quality = CONSTRUCTIVE.

That is acceptable, but it should not be treated the same as runaway chase extension.

Add:

confluence_v42.risk.caution_flags
caution_flags

Rules:

If extension_state == "EXTREME_EXTENSION" and extension_quality == "CONSTRUCTIVE" and chase_extension == false:
- remove EXTREME_EXTENSION from red risk_flags if currently present
- add EXTREME_EXTENSION_CONSTRUCTIVE_RESET to caution_flags

If extension_state == "EXTREME_EXTENSION" and extension_quality != "CONSTRUCTIVE":
- keep EXTREME_EXTENSION in risk_flags

If chase_extension == true:
- keep CHASE_EXTENSION in risk_flags

Frontend can render caution_flags as amber.
