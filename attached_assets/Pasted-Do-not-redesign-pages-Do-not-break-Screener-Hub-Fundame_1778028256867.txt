Goal:
Ensure all FMP-backed screeners/pages share the same canonical FMP cache and never duplicate FMP calls for the same ticker/data type across pages.

Current problem:
Multiple pages can independently need the same FMP-backed fields:
- Thematic Screener
- Social Screener
- Watchlist+Portfolio Screener
- Fundamentals page
- Calendar/catalyst features
- any other FMP-backed screeners

We need one shared FMP cache/read-through layer so the same ticker/data type fetched once can be reused everywhere.

Part 2 — Add/confirm canonical FMP cache interface

Create or consolidate a shared service, for example:
backend/services/fmp_cache_service.py

It should expose cache-first functions like:
- get_company_profile_cached(symbol)
- get_company_profiles_cached(symbols)
- get_fundamentals_cached(symbol)
- get_screener_metadata_cached(symbol)
- get_stock_screener_snapshot_cached(theme_or_filter_key)
- get_historical_returns_cached(symbol)
- get_peers_cached(symbol)

Rules:
1. All functions read cache first.
2. No page-load function should call FMP unless explicitly allowed.
3. FMP network calls require:
   - source_job_name
   - endpoint_group
   - force=false/true
   - budget governor check
4. Cache key should include:
   - provider = fmp
   - endpoint_group
   - symbol or filter_hash
   - as_of_date / fetched_at
5. Same ticker + same endpoint_group fetched within TTL should never call FMP again.

Part 3 — Canonical cache tables or reuse existing tables

- screener_returns_cache

Part 7 — Fallback behavior

If FMP budget/cache unavailable:
- serve stale cached data if present
- otherwise return null for non-critical fields
- do not crash page
- do not trigger emergency FMP calls from page load
