Goal:
One-shot fix Screener Hub selected-theme behavior.

Current user-facing failure:
The default theme works, but when the user selects another theme from the dropdown, the screener often returns empty/weak results.

Example from UI:

Theme: AI Networking
Market Cap: $10B+
Screen says: Universe fresh, Quotes fresh, Partial data
Showing: AI Networking · Custom screen · MCap: $10B+
Result: No rows / limited screenable results

This is unacceptable. If the user explicitly selects a theme, that selected theme must run through the same full screener pipeline as the default theme and return real hydrated rows if available.

This is not a frontend issue anymore. Frontend is sending the selected theme. Backend must make selected themes first-class screens.

Core product behavior required:

No theme param → use daily default theme.
Explicit theme param → serve that exact selected theme.
If selected theme cache is stale, missing, weak, or under-hydrated, refresh/hydrate it on demand before returning results, when allowed by the 24h cap.
Hydrate fundamentals/market cap/sector/industry/price/volume/options before applying user filters.
Then apply Market Cap, Min Volume, Exchange, Score Mode.
Return clean screenable rows, not stale shells.
Only show limited/empty results after refresh was attempted or blocked by cap/concurrency/failure.
No repeated FMP hammering.

Important:
The old behavior of scheduling a background refresh and immediately returning a weak cached result is not acceptable for explicit user-selected themes. For explicit selected themes, if refresh is allowed, refresh inline before response.

Part 3 — Inline refresh for explicit selected themes

For explicit theme requests:

GET /api/screener-hub?tab=thematic&theme={theme_key}

If the theme is:

missing cached universe
older than 24h
weak cache
low metadata coverage
mostly missing market_cap/price/volume before filters
returns zero rows after filters because hydration is missing

Then if FMP refresh is allowed:

run the safe per-theme refresh inline/synchronously before returning
use a reasonable timeout, 8–15 seconds
reload refreshed data
hydrate rows
apply filters
return the refreshed result

Set:

theme_refresh_status = "refreshed_inline" or "stale_refreshed"
fmp_refresh_used = true
fmp_refresh_reason = "explicit_theme_stale_or_weak"
theme_last_refreshed_at
theme_next_refresh_allowed_at

If refresh is blocked by 24h cap:

do not call FMP
return theme_refresh_status = "stale_cap_active"
return honest warning

If refresh is already in-flight:

wait briefly if possible
otherwise return theme_refresh_status = "refreshing"

If concurrency cap is full:

return theme_refresh_status = "refresh_queued"
do not spawn unlimited tasks

Part 4 — FMP usage rules for selected theme refresh

Allowed for explicit selected theme refresh:

FMP screener/theme stock requests needed to build that selected theme
once per theme per 24 hours
only when selected theme is stale/weak/missing or explicitly needs hydration
existing safe/ranged historical calls only if already part of current safe pipeline

Not allowed:

any LLM call
/stable/historical-price-eod/full
ETF quote loops
repeated FMP calls on every click
refreshing all 60 themes because one theme was selected

The user has FMP room now, but the guardrails still matter.

Part 5 — Hydrate before applying filters

This is critical.

For explicit selected themes:

Refresh/hydrate the selected universe first.
Then apply filters.

Market Cap $10B+ should not return zero just because market_cap was missing before hydration.

Filter policy:

If market cap filter active and market_cap is still missing after hydration, exclude row and count it.
If min volume filter active and volume is still missing after hydration, exclude row and count it.
If exchange filter active, apply the documented exchange policy consistently.

Part 6 — Selected theme should never silently fallback to default

Rules:

No theme param → use daily default.
Explicit theme param → use requested theme.
Invalid theme → UNKNOWN_THEME JSON error.
Weak selected theme → selected theme response with warning, not default rows.
Empty selected theme after refresh attempt → empty response with clear message, not default rows.
