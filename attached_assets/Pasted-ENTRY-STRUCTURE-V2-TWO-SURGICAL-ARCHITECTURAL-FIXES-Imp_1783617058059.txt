FIX 1 — STRUCTURE ANALYSIS MUST NOT BE DISABLED BY EXTENSION
============================================================

Current behavior:

DELL:
extension_pct ≈ +103.9% vs 30-week MA
extension_state = EXTREME_EXTENSION

The current Entry State V2 gate prevents structural V2 classification when extension_state == EXTREME_EXTENSION.

As a result:

structure_v2 = unavailable/not consumed by the V2 classification branch
DELL falls into legacy CHASE_EXHAUSTION / AVOID
Entry score = 8

This is conceptually wrong.

STRUCTURAL GEOMETRY and EXTENSION RISK are separate dimensions.

A ticker may simultaneously be:

HIGH_BASE_READY
+
EXTREME_EXTENSION

or:

TRENDLINE_SUPPORT_TEST
+
EXTENDED

or:

BREAKOUT_RETEST
+
MODERATELY_EXTENDED

Entry Structure must answer:

WHAT STRUCTURE EXISTS?

Extension must answer:

HOW STRETCHED IS THE TICKER RELATIVE TO LONGER-TERM TREND?

Extension may modify score, grade, risk, and later Actionability.

Extension must NOT prevent the structural engine from detecting the chart geometry.

---

## REQUIRED CHANGE

Inspect the current V2 classification gate in:

backend/services/entry_state_service.py

The current gate includes an exclusion equivalent to:

extension_state != EXTREME_EXTENSION

Remove EXTREME_EXTENSION as a condition that prevents V2 structural analysis/classification.

`compute_structure()` should remain available for any symbol with sufficient daily bars.

The V2 classifier should evaluate:

base structure
breakout structure
trendline structure
structural support

regardless of extension state.

---

## EXTENSION REMAINS A RISK INPUT

Do NOT ignore extension.

Use the existing:

extension_state
extension_pct
extension_atr where available

as a scoring/risk modifier AFTER structural classification.

Examples of intended behavior:

HIGH_BASE_READY + HEALTHY
→ very strong Entry score

HIGH_BASE_READY + MODERATELY_EXTENDED
→ strong Entry score with moderate extension risk

HIGH_BASE_READY + EXTENDED
→ reduced Entry score / risk reason

HIGH_BASE_READY + EXTREME_EXTENSION
→ materially reduced Entry score and potentially lower grade, but structure remains HIGH_BASE_READY if the daily geometry actually qualifies

BREAKOUT_CONFIRMED + EXTREME_EXTENSION
→ likely WAIT_FOR_RETEST / chase-risk interpretation

NO_BASE + VERTICAL + EXTREME_EXTENSION
→ CHASE_EXHAUSTION / EXTREME_EXTENSION remains appropriate

The engine must distinguish:

EXTREME_EXTENSION WITH NO CONSOLIDATION

from:

EXTREME_EXTENSION RELATIVE TO 30W MA BUT CURRENTLY IN A MATURE DAILY HIGH BASE

The latter is the DELL-type structural question.

Do not hardcode DELL.

FIX 2 — V2 STRUCTURE MUST NOT FALL THROUGH TO LEGACY FAILURE HEURISTICS
=======================================================================

Historical replay found a real bug in CIFR.

CIFR V2 structure:

base_breakout_status = BREAKOUT_IN_PROGRESS
breakout_confirmed = true / prior structural breakout exists
failed_breakout_confirmed = false
failed-breakout reason = pivot_holding
trendline_hold_state = HELD_RECENTLY
base support intact

But final Entry State:

FAILED_BREAKOUT

Reason:

`BREAKOUT_IN_PROGRESS` is not handled by the explicit V2 override branches.

The classifier falls through to the legacy classifier.

The legacy classifier applies:

breakout_sig=failed_breakout_fallback_no_structure

and overrides the richer V2 structural result.

This must not happen.

---

## ARCHITECTURAL RULE

Legacy classification may be used when:

structure_v2 failed to calculate
structure_v2 is unavailable
daily bars are insufficient
V2 returns no usable structural bundle

Legacy classification must NOT override a successfully computed V2 structural bundle merely because a V2 enum/status lacks an explicit branch.

If:

structure_v2 is valid

AND

strict V2 failed_breakout_confirmed == false

then the legacy naive failed-breakout heuristic must NEVER return FAILED_BREAKOUT.

---

## HANDLE BREAKOUT_IN_PROGRESS

Add an explicit deterministic V2 classification path for:

base_breakout_status == BREAKOUT_IN_PROGRESS

Use the current structural fields.

Possible justified outputs:

BREAKOUT_CONFIRMED
BREAKOUT_PULLBACK
WAIT_FOR_RETEST
SIGNALS_BUILDING

depending on:

current position vs pivot
breakout confirmation
distance from pivot
extension
trendline/base support
recent close behavior

Do not create a new state solely for CIFR unless structurally necessary.

---

## V2 SAFE FALLBACK

After explicit V2 branches, if a valid V2 structure bundle exists but no specialized state matches:

return a V2-safe neutral structural state such as:

NO_CLEAR_ENTRY

or an existing equivalent

with V2 evidence/reason codes.

Do NOT call the legacy classifier in that case.

Legacy classifier remains only for:

no usable V2 structure

This creates a clean architectural boundary:

V2 STRUCTURE AVAILABLE
→ V2 is authoritative

V2 STRUCTURE UNAVAILABLE
→ legacy fallback
