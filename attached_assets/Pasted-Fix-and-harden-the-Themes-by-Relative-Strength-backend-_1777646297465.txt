Fix and harden the Themes by Relative Strength backend implementation.

Goal:
Create a canonical, production-ready theme relative strength backend that:
1. Tracks all 39 screenshot themes.
2. Uses ETFs/proxies to measure theme performance.
3. Uses dynamic holdings/discovery for leaders and laggards wherever possible.
4. Does NOT hardcode final leader/laggard stocks except as last-resort fallback.
5. Does NOT touch Chain Reaction yet.
6. Does NOT touch Earnings.
7. Does NOT touch Options Flow.
8. Does NOT touch TA Screener.
9. Uses no LLM calls for core calculations.

Now make the implementation correct.

Core principle:
Theme proxy symbols can be configured.
Final leaders/laggards should be dynamically discovered wherever possible.

Do NOT treat candidate_symbols/static representatives as the final leader/laggard universe unless all dynamic sources fail.

Provider roles:
1D / current quote:
- Tradier quote/change primary
- FMP daily history fallback
- yfinance emergency fallback only

7D / 30D / YTD / 1Y historical returns:
- FMP historical daily prices primary
- Tradier historical daily prices fallback
- yfinance emergency fallback only

Do not use yfinance as the normal primary historical engine.

Theme performance:
For each theme:
- Use proxy_symbols / ETFs to calculate the theme return.
- For clean ETF themes, use the primary ETF/proxy return or median of proxy ETFs.
- For hybrid themes, use proxy ETFs first, then basket fallback only if ETF data is unavailable.
- Calculate:
  - 1D return
  - 7D return
  - 30D return
  - YTD return
  - 1Y return
  - RS vs SPY
  - RS vs QQQ
  - rs_score
  - breadth
  - state: active / emerging / neutral / weakening / dead_zone

Leader/laggard universe:
For each theme, build the leaders/laggards universe dynamically in this order:
1. ETF holdings from existing ETF holdings service for proxy_symbols_used.
2. FMP peers from top ETF holdings / anchor proxy names.
3. Cached X/Grok consensus tickers if already mapped to that theme.
4. Existing Dynamic Thematic Universe source attribution if available.
5. Static candidate_symbols only as last-resort fallback seeds.

Important:
- candidate_symbols/static representatives are allowed as fallback seeds.
- They are not allowed to be the only/default leaders/laggards universe when ETF holdings or dynamic sources are available.
- Do not add new X/Grok calls. Only read existing cached X/Grok consensus if already available.
- Do not add LLM calls.
- Do not rely on unsupported FMP bulk endpoints.

Memory & Storage special handling:
- Use DRAM as the primary proxy if any provider can return valid data.
- Provider order for DRAM:
  1. FMP historical / daily data
  2. Tradier historical / quote data
  3. yfinance emergency fallback
- If DRAM is unavailable or invalid, fall back to SMH/SOXX.
- Leaders/laggards should come from DRAM holdings if available.
- If DRAM holdings are unavailable, use SMH/SOXX holdings, then FMP peers, then cached X/Grok, then static fallback.
- Do NOT hardcode MU/WDC/STX/SIMO as the only Memory & Storage leader/laggard universe.
