Implement the minimal backend side of “agent sees what I see” based on the completed audit.

Scope:
Backend only.
Do not touch frontend files.

Work in the backend Replit project only.

Goal:
Make /api/query accept, preserve, compress, route with, and inject frontend-provided screen/page context into the agent reasoning path.

Current audit finding:
- QueryRequest has no page_context / screen_context field.
- extra="ignore" likely drops any frontend-provided page context.
- The agent is currently page-blind by default.
- Several page data sources exist but are not reachable by the agent.

Backend tasks:

1. Add screen_context support to /api/query
- Locate the /api/query request schema/model.
- Add a field named `screen_context` or `page_context`. Prefer `screen_context`.
- It should accept a flexible dict/object payload.
- Do not silently drop this field.
- Preserve at least:
  - route
  - page
  - tab
  - selected_symbol
  - visible_symbols
  - filters
  - sort
  - visible_rows
  - rendered_sections
  - tradingview_context
  - freshness/cache metadata

2. Inject screen_context into the agent path
Trace the existing flow:
/api/query → query_agent() → TradingAgent.handle_query() or the current equivalent path.

Make sure screen_context is included in:
- intent/category routing hints
- user context / agent context bundle
- final LLM synthesis prompt
- collaborator context if the collaborator path supports it

The agent should be able to answer questions like:
- “What looks good here?”
- “Which of these are strongest?”
- “What’s the best setup on this page?”
without needing the user to restate the current page.

3. Safe compression / token handling
- Add defensive size limits.
- Do not dump unlimited rows into the prompt.
- Prioritize high-signal fields.
- Preserve qualitative signal text better than the current 200-character hard truncation where possible.
- Avoid cutting off Grok/social analysis, filing descriptions, analyst summaries, earnings notes, or conviction explanations into useless stubs.
- Include counts/metadata for omitted rows.

Recommended compression priority:
- page, route, tab
- selected_symbol
- visible_symbols
- visible row count
- top visible rows
- active filters/sort
- high-signal rendered section summaries
- tradingview symbols/timeframes
- freshness/cache status
