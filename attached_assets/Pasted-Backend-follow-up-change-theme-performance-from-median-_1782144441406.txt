Backend follow-up — change theme performance from median to equal-weight average

The audit confirmed theme performance currently uses:

statistics.median(per_symbol_returns)

But the intended behavior is equal-weight average percentage change across the tracked theme basket.

Goal:
Change Themes page performance calculation for 1D, 7D, 30D, YTD, 1Y, and 5Y from median return to arithmetic mean return across valid tracked symbols.

Important:

* representative_symbol / tv_symbol remains chart-only.
* theme_holdings remains saved/imported theme universe + manual/watchlist snapshot additions/removals.
* performance_symbols/proxy_symbols remains the performance basket.
* Missing symbols should still be skipped, not counted as zero.
* Do not change Watchlist behavior.
* Do not re-enable live Watchlist dependency.
* Do not reintroduce live ETF holdings fetches.
* Do not change manual add/remove/leader semantics.

Required behavior:

1. _compute_theme_perf() should calculate:
   sum(valid_symbol_returns) / count(valid_symbol_returns)
2. Round the same way as before.
3. Missing/no-data symbols are excluded from denominator.
4. Return null/None only if no valid symbols exist.
5. Add or update debug metadata to report:

   * performance_method: "equal_weight_average"
   * performance_symbol_count
   * valid_symbol_count
   * skipped_symbol_count
6. Ensure no code path still reports median unless explicitly named historical/debug.
