Backend only.

Do not touch frontend.
Do not change Confluence score weights.
Do not hardcode ticker symbols.
Do not add provider calls.
Do not call LLMs.
Do not change options/catalyst/investment formulas.
Do not loosen every threshold blindly.

Goal:

V4.2.3 fixed the decision layer, but the audit shows remaining false negatives are mostly caused by:

1. Missing setup labels / pattern variants.
2. Entry/Exit scoring being too narrow for real-world pullbacks, prior-high retests, high-base consolidations, right-side cup structures, and moving-average pullbacks.

This is a generic setup/entry calibration, not a ticker allowlist.

The engine should recognize more valid bullish setup families without simply making everything actionable.

PART 2 — ADD HIGH-BASE / MOMENTUM CONSOLIDATION SETUP
==================================================

Add generic setup detection/mapping for high-base consolidation and momentum consolidation.

This should catch tickers like VRT conceptually, but do not hardcode VRT.

Definition:

HIGH_BASE_CONSOLIDATION / MOMENTUM_CONSOLIDATION can be inferred when:

- stage_quality_points >= 10.5
- price/support status is above_support or bounced_from_support
- active support is not lost
- extension is not chase_bad
- stock is consolidating near highs or has strong relative structure if those fields exist
- entry_exit_points >= 6.0
- no confirmed lower low
- no support_lost

If exact near-high/range-contraction fields exist, use them.

If they do not exist, use existing support/status/stage/entry fields as fallback.

Assign:

technical_setup_label = High-Base Consolidation
technical_setup_direction = bullish
technical_setup_raw_score = 65–85 depending quality
technical_setup_points should usually land >= 4.5/8 when entry/stage are strong.

Do not turn every above_support stock into high-base consolidation.

Require:

stage quality
entry quality
intact support
no chase_bad
no confirmed breakdown

==================================================
PART 3 — ADD MOMENTUM PULLBACK / PRIOR-HIGH / MA RETEST ENTRY
==================================================

Entry/Exit currently misses clean pullbacks that are not sitting exactly on the one active support level.

Add generic entry detection for:

MOMENTUM_PULLBACK_ENTRY
PRIOR_HIGH_RETEST_ENTRY
BREAKOUT_SHELF_RETEST_ENTRY
MOVING_AVERAGE_PULLBACK_ENTRY

Valid pullback/retest entry levels include:

- prior high
- breakout shelf
- reclaim level
- active support
- rising 20-day moving average
- rising 30-day moving average
- rising 50-day moving average
- rising 200-day moving average
- Fib / prior-high retest level if already available

Important:

The 200-day moving average should be treated as a major valid entry/retest level when price is reclaiming it, holding it, or pulling back into it constructively.

Do not only reward short/intermediate MA pullbacks. 20/30/50/200 MA pullbacks can all be valid entries depending on context.

General conditions:

- eligible
- no risk conflict
- stage_quality_points >= 8.5
- active support not lost
- not confirmed lower low
- not failed breakdown
- price has pulled back/retested into a recognized level:
  prior high
  breakout shelf
  reclaim level
  active support
  20DMA / 30DMA / 50DMA / 200DMA if available
  Fib/prior-high level if available
- entry_exit_points >= 4.25 initially OR entry score can be upgraded by this detection
- technical_setup_points >= 4.0 OR setup label is high-tight / bull flag / breakout shelf / high-base / momentum pullback / MA pullback

If exact Fib data is unavailable, do not fabricate it.

If exact MA fields exist, use them.

If MA fields do not exist, do not add provider calls. Use already-available technical/support fields only and expose MOVING_AVERAGE_DATA_UNAVAILABLE as a reason code.

Reason codes:

MOMENTUM_PULLBACK_ENTRY
PRIOR_HIGH_RETEST_ENTRY
BREAKOUT_SHELF_RETEST_ENTRY
MOVING_AVERAGE_PULLBACK_ENTRY
DMA20_PULLBACK_ENTRY
DMA30_PULLBACK_ENTRY
DMA50_PULLBACK_ENTRY
DMA200_PULLBACK_ENTRY
DEFINED_RISK_PULLBACK

This should help cases like ALGM generically:

strong setup, stage 15, high-tight continuation, bounced_from_support, entry=4.44 just below the old hard floor.

Do not make weak-stage/no-setup names actionable just because they dipped.

==================================================
PART 4 — DISTINGUISH CHASE EXTENSION FROM CONSTRUCTIVE PULLBACK
==================================================

Current issue:

Some tickers are being treated as Chase Extension even if they have already pulled back constructively.

A ticker can be extended historically and still become buyable after a constructive reset.

Add logic:

If chase_extension=True but:

- support_status is bounced_from_support or above_support
- active support not lost
- entry has improved from extreme/poor to at least moderate
- stage_quality_points >= 9
- technical structure suggests low-base continuation / momentum pullback / reversal continuation / MA pullback
- price is holding or reclaiming a valid support/retest level

then downgrade blocker from hard WATCH_FOR_RESET_CHASE_EXTENSION to:

CONSTRUCTIVE_PULLBACK_AFTER_EXTENSION

This should allow:

- NEAR_ACTIONABLE or ACTIONABLE_NOW if entry/setup thresholds pass
- not automatic Actionable

Keep true chase blocked when:

- price remains far above support
- no reset
- no support/retest
- no MA/pullback/reclaim evidence
- extension_state is EXTREME_EXTENSION and entry_exit_points remains very low
- support is not nearby

Do not blindly flip all chase_extension names.

==================================================
PART 5 — ADD RIGHT-SIDE CUP / STAGE 1 ACCUMULATION PATH
==================================================

SOFI-like setups should not be treated like dead setups just because Stage score is low.

Add a separate early setup tier:

EARLY_ACTIONABLE
EARLY_ACCUMULATION
RIGHT_SIDE_CUP_ENTRY

This is not the same as ACTIONABLE_NOW.

Conditions:

- eligible
- no risk conflict
- investment_quality_score >= 70 OR investment_alignment_points >= 10
- entry_exit_points >= 4.5
- no support_lost
- no confirmed lower low
- no Stage 4 / major breakdown
- technical setup suggests right-side cup, accumulation, rounded base, reclaim, or strong rebound from lows if available
- if 200DMA reclaim / 200DMA support is available, this should be treated as especially meaningful for Stage 1 to Stage 2 transition setups

Possible labels:

RIGHT_SIDE_CUP
STAGE1_ACCUMULATION
EARLY_BASE_BUILDING
RIGHT_SIDE_MOMENTUM
DMA200_RECLAIM_BASE

Decision:

- if these pass, set actionable_tier = EARLY_ACTIONABLE or NEAR_ACTIONABLE
- do not call it ACTIONABLE_NOW unless entry/setup evidence is much stronger

This should let SOFI-type setups surface as early opportunities without pretending they are mature Stage 2 breakouts.
