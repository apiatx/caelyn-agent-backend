Fix the Portfolio toggle on Calendar → Earnings using the now-working Portfolio page source of truth.

Backend repo:
apiatx/caelyn-agent-backend

Current confirmed architecture:
- Portfolio page is now working.
- User manually adds portfolio assets/stocks/tickers on the Portfolio page.
- Saved Portfolio holdings are stored in Neon.
- Neon is connected to the backend FastAPI server through the existing Portfolio API.
- The Portfolio page is now the source of truth for active portfolio holdings.

Goal:
Calendar → Earnings → Portfolio toggle should display earnings events for the exact same stock tickers currently saved on the Portfolio page.

This must behave like the already-working Watchlist toggle:
- Watchlist toggle pulls saved Watchlist tickers and renders them in earnings calendar style.
- Portfolio toggle should pull saved Portfolio holdings/tickers and render them in the same earnings calendar style.

Do not touch:
- All toggle
- Watchlist toggle
- curated/thematic All earnings logic
- Portfolio page CRUD behavior
- frontend unless specifically needed after backend validation

Core requirement:
For scope=portfolio on the Earnings Calendar:
1. Load active Portfolio tickers from the same Neon-backed Portfolio API/service used by the Portfolio page.
2. Fetch/cache their next earnings events.
3. Fetch/cache their most recent/last earnings event details where available.
4. Attach the same live price / percent change fields using the existing Tradier quote path used for Portfolio/Watchlist quote hydration.
5. Return the same route-specific response shapes that the Watchlist earnings calendar already returns, so the frontend can render Portfolio exactly like Watchlist.

Important:
Do not use any legacy local JSON portfolio file.
Do not use stale demo holdings.
Do not use portfolio_holdings_default.json unless the Portfolio page itself still uses it, which it should not if Neon is now the source.
Do not union multiple portfolio files.
Do not use Watchlist symbols.
Do not use curated All symbols.
Do not client-provide ticker lists.

The only valid source is the active Portfolio holdings saved in Neon through the working Portfolio page API.

- 0 FMP calls on repeat cache-hit requests
