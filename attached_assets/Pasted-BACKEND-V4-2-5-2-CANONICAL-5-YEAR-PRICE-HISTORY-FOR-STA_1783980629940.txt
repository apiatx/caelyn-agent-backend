BACKEND — V4.2.5.2 CANONICAL 5-YEAR PRICE HISTORY FOR STAGE + ENTRY + FIB

Backend only.

Do not touch frontend.
Do not change Confluence weights.
Do not hardcode ticker symbols.
Do not call LLMs.
Do not add request-time provider calls.
Do not change Options, Catalyst, Investment, Social, or Actionability formulas.
Do not rewrite the V4.2.5.1 Fib engine unless necessary to consume the new canonical history source.
Do not break retained snapshot rebuild speed.

Goal:

The system currently has inconsistent bar depth:

ABCL / ALGM / VRT: ~1300 bars / ~5.2 years
CRDO / MARA: ~400 bars / ~1.6 years
WYFI: ~200 bars / ~0.8 years

Some of this may be legitimate if the ticker is new.
But if a ticker has more than 400 bars available and the backend only sees 400, that is a cache/code-path problem.

The user’s technical system depends heavily on 1–5 year structures:
- Stage analysis
- 200DMA / 30-week SMA context
- multi-year bases
- Stage 1 → Stage 2 transitions
- Fibonacci anchors
- extension/reset logic
- right-side cup / accumulation structures

Therefore, Stage, Entry/Exit, Extension Reset, Fib, and Wave Structure should all consume a canonical long-history price source when available.

FMP Starter supports up to 5 years of historical daily price data.
400 bars is not the provider max. It is a current code/cache choice.

PART 3 — PROVIDER STRATEGY
==================================================

Provider order:

1. Existing canonical 5-year cache if fresh.
2. Tradier only if it can return the requested 5-year daily range reliably.
3. FMP fallback for up to 5 years.
4. Existing 400-bar Stage cache as last fallback.

Important:

Do not assume Tradier can return 5 years until audited.
If Tradier returns partial history:
- mark partial_history
- fall back to FMP if budget allows

FMP rules:

- Use existing FMP budget governor if available.
- No request-time FMP calls.
- No frontend-triggered FMP calls.
- No duplicate call if cache is fresh.
- Respect monthly usage/budget constraints.
- Space calls safely.
- Make the job resumable.

Backfill cadence:

- weekly off-hours refresh for eligible universe
- max symbols per run
- delay between provider calls
- persistent progress
- skip fresh 5-year cache rows
- prioritize symbols with stale/partial/no long-history cache

==================================================
PART 4 — STAGE MUST USE CANONICAL LONG HISTORY
==================================================

Current Stage behavior uses ~400 daily bars.
That is not enough for the final system.

Update Stage analysis to prefer canonical 5-year bars when available.

Stage may still calculate:

- 30-week SMA
- 4-week slope
- 26-week prior trend
- 8-week RS
- 20/50/200DMA

But it should calculate them using a full long-history input when available.

Why:

A 400-bar window can misclassify:
- multi-year Stage 1 accumulation
- Stage 1→2 transitions
- late Stage 2 vs early Stage 2
- multi-year bases
- long-term 200DMA reclaim structures
- major cycle lows/highs

Do not change Stage formula unnecessarily.
Change the data depth feeding Stage.

Expose Stage history diagnostics:

stage_bar_count
stage_years_available
stage_history_status
stage_history_source
stage_long_history_used
stage_data_limitation_reason

If only 400 bars exist:
- Stage can still run
- but stage_history_status should not pretend 5-year context exists

PART 7 — CONFIDENCE MUST ACCOUNT FOR DATA DEPTH
==================================================

Do not let a 400-bar Fib or Stage result have the same long-term confidence as a 1300-bar result.

Add separate confidence fields:

history_data_depth_confidence
stage_data_depth_confidence
fib_data_depth_confidence
entry_data_depth_confidence

Suggested data depth confidence:

1300+ bars / ~5y = 1.00
756–1299 bars / ~3–5y = 0.85
504–755 bars / ~2–3y = 0.70
252–503 bars / ~1–2y = 0.50
<252 bars = 0.25 max unless ACTUAL_TICKER_HISTORY_LIMIT

If ticker is genuinely new:
- use actual_ticker_history_limit
- do not penalize as provider failure
- but do not label it multi-year
