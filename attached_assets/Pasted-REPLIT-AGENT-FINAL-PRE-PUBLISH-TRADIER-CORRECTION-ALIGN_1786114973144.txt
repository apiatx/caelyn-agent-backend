────────────────────────────────────────────────────────────
DEFECT 1 — GLOBAL SLOT IS RESERVED TOO EARLY
────────────────────────────────────────────────────────────

Current 78a5793c Theme RS intraday ordering is approximately:

cache
→ lane check
→ try_acquire_background()
→ record global timestamp
→ record lane call
→ wait for _INTRADAY_SEM
→ HTTP

This is incorrect.

The global limiter timestamp should correspond closely to the physical HTTP
request.

If many tasks reserve global slots before they acquire the 20-wide semaphore,
some requests may execute materially later than the timestamps representing
them.

This can make the 60-second global window undercount actual future HTTP traffic.

Correct it.

Because background admission is now NON-BLOCKING, there is no problem doing:

cache/coalescing
→ acquire _INTRADAY_SEM
→ lane check
→ non-blocking global admission
→ record lane call
→ HTTP IMMEDIATELY
→ release semaphore

There must be NO sleeping Tradier limiter call inside the semaphore.

A synchronous lane check and the non-blocking try-acquire are acceptable while
holding the semaphore because neither waits for a reset.

Required invariant:

A successful global admission timestamp must be immediately followed by the
corresponding physical HTTP call, with no unrelated concurrency queue between them.
