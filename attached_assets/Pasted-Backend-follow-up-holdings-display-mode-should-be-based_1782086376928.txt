Backend follow-up — holdings_display_mode should be based on true basket/enrichment, not only proxy_type

Good fix on separating representative_symbol from theme holdings. But the current holdings_display_mode rule is still too broad:

custom/hybrid → theme_basket
etf/basket → etf_holdings

That is not fully correct.

A theme can have proxy_type = etf but still be watchlist-enriched or manually curated. In that case, the expanded view should show the true theme basket, not the full holdings of the representative ETF.

Core rule:
Only use ETF holdings when the theme is truly ETF-only and has no curated/manual/watchlist-added basket.

Required behavior:

1. representative_symbol remains chart-only.
2. performance_symbols/proxy_symbols remain the merged performance basket.
3. theme_holdings/display_symbols should show the true symbols the theme is tracking.
4. holdings_display_mode should be:

   * "theme_basket" when the theme has curated/manual symbols, watchlist-added symbols, source_type = merged/watchlist_enriched/watchlist_only, or proxy_type = custom/hybrid/basket where basket is manually curated.
   * "etf_holdings" only when the theme is truly ETF-only and the ETF holdings are intentionally the theme representation.
5. Do not rely only on proxy_type.
6. Do not show ETF constituent holdings for a representative ETF unless holdings_display_mode = etf_holdings.
7. Do not change performance math.
8. Do not touch Watchlist files.

Correct mode logic:
Use "theme_basket" if any of these are true:

* watchlist_added_symbols.length > 0
* source_type is merged/watchlist_enriched/watchlist_only
* proxy_type is custom
* proxy_type is hybrid
* proxy_type is basket and the symbols are manually curated
* display_symbols/theme_holdings were explicitly provided

Use "etf_holdings" only if:

* no watchlist_added_symbols
* no manually curated display_symbols
* the theme is intentionally represented by ETF holdings
* representative_symbol is an ETF
* expanded holdings are meant to show that ETF’s holdings
