INTENDED METRIC

VOL RANK means:

change in a ticker's relative-volume rank POSITION versus the other stocks in the same active Watchlist between the current and previous rank snapshot.

Example:

Previous snapshot:

1 NVDA
2 MU
3 AMD
4 IREN

Current snapshot ranked by relative_volume descending:

1 MU
2 AMD
3 IREN
4 NVDA

Result:

MU:
previous_rank=2
current_rank=1
rel_vol_rank_delta=+1
rel_vol_trend="up"

AMD:
previous_rank=3
current_rank=2
rel_vol_rank_delta=+1
rel_vol_trend="up"

IREN:
previous_rank=4
current_rank=3
rel_vol_rank_delta=+1
rel_vol_trend="up"

NVDA:
previous_rank=1
current_rank=4
rel_vol_rank_delta=-3
rel_vol_trend="down"

The column is NOT:

current rank
volume percent change
change in raw volume
change in relative_volume itself

It is rank-position movement in relative-volume leadership across the Watchlist universe.

PART F — DEFINE THE RANK MATH EXPLICITLY

For one Watchlist snapshot:

1. collect all Watchlist tickers with valid canonical relative_volume
2. normalize ticker identity using the existing canonical Watchlist symbol rules
3. sort:
   relative_volume descending
4. deterministic tie breaker:
   canonical ticker ascending
5. assign ranks starting at 1

Then compare with the immediately previous completed snapshot for that same watchlist_id.

Use:

rank_delta =
previous_rank - current_rank

Therefore:

previous 20
current 5
→ +15

Ticker moved UP 15 positions.

previous 5
current 20
→ -15

Ticker moved DOWN 15 positions.

Required response fields:

rel_vol_current_rank
rel_vol_previous_rank
rel_vol_rank_delta
rel_vol_trend

Trend rules:

delta > 0
→ "up"

delta < 0
→ "down"

delta == 0
→ "flat"

no prior rank for ticker
→ "unknown"

No current valid relative_volume
→ preserve unavailable state following current row conventions

Do not invert the sign.

PART G — DEFINE WHAT "PREVIOUS SNAPSHOT" MEANS

Audit the old intended cadence before changing it.

The rank movement should represent a meaningful recent movement interval.

Preferred architecture unless the existing implementation has a clearly established better cadence:

Use a lightweight backend rank snapshot driven by existing canonical quote refresh state.

approximately every 5 minutes during active market-data operation

Do not use page-load cadence.

Do not fetch quotes inside the rank job.

At snapshot time:

read the already-warm canonical relative-volume values

Keep:

previous completed snapshot

or an equivalent bounded history sufficient for rank delta.

If an existing rank-snapshot cadence already exists, preserve it unless audit proves it is the performance problem.

Report the final cadence explicitly.
