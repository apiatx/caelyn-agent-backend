* Same ticker can belong to multiple themes.

* representative_symbol remains chart-only ETF/proxy.

* Do not change Watchlist behavior.

Fix 2 — persistent theme leader:
Add persistent dev/admin theme leader support.

Preferred storage:
Create a Neon table, or equivalent existing migration pattern:

theme_leader_overrides:

* theme_id text primary key
* leader_symbol text not null
* source text default 'manual_admin'
* note text nullable
* created_by text nullable
* created_at timestamptz default now()
* updated_at timestamptz default now()

Rules:

1. One manual leader per theme.
2. Same symbol can be leader for multiple themes if manually chosen.
3. leader_symbol should normally be a member of that theme’s final basket.
4. If user marks a symbol leader and it is not currently in the theme basket, either:

   * reject with 400 and explain symbol must be in the theme basket first,
   * or add it to that theme automatically, but only if explicitly implemented and documented.
     Prefer rejection unless existing UI flow requires auto-add.
5. Removing a ticker that is currently the manual leader should either:

   * clear the leader for that theme,
   * or reject removal until leader is changed.
     Prefer clearing leader automatically and return that in response.
6. Clearing/deleting the leader restores default behavior.
