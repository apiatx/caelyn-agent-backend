New feature:
On the Watchlist page ticker table, we want tickers with increasing relative volume / volume momentum that are moving up the list to show green, and tickers with falling relative volume / moving down the list to show red.

Backend should add additive fields to each ticker row:
- rel_vol_rank: number | null
- rel_vol_prev_rank: number | null
- rel_vol_rank_delta: number | null
- rel_vol_trend: "up" | "down" | "flat" | "unknown"
- rel_vol_value_delta: number | null
- rel_vol_prev_value: number | null
- rel_vol_momentum_label: "surging" | "rising" | "fading" | "falling" | "flat" | "unknown"

Definition:
- Sort eligible tickers by current relative_volume descending.
- rel_vol_rank = current rank among rows with numeric relative_volume.
- Compare against the prior watchlist snapshot/ranking.
- If current rank number is lower than previous rank, the ticker moved up.
  Example: previous rank 40, current rank 12 => rel_vol_rank_delta = +28, trend = "up"
- If current rank number is higher than previous rank, the ticker moved down.
  Example: previous rank 10, current rank 35 => rel_vol_rank_delta = -25, trend = "down"
- If no previous snapshot exists, trend = "unknown".
- If current or previous relative_volume is missing, trend = "unknown" unless rank comparison is still safe.

  watchlist_id

  rank
  captured_at
- Keep only recent snapshots, e.g. latest/current and previous, or a rolling 24h retention.
- On each successful enrichment:
  1) build current ranks from rows with numeric relative_volume
  2) load previous ranks for the same watchlist_id
  3) compute trend/delta fields
  4) return additive fields in ticker rows
  5) save current snapshot for next comparison
- Avoid writing a snapshot if quote coverage is extremely low due to provider outage, because that would create garbage trend signals.
  Example guard: only snapshot when at least 50% of saved US-eligible symbols have relative_volume.
- For foreign/unsupported tickers, trend should be "unknown".

Fallback implementation if persistent snapshot is too much:
- Use in-memory TTL cache only as a temporary fallback.
- But prefer Neon/durable cache so page refresh/restart does not erase movement history.

Momentum label guidance:
- If rel_vol_trend = "up" and rel_vol_rank_delta >= 10, label "surging"
- If rel_vol_trend = "up", label "rising"
- If rel_vol_trend = "down" and rel_vol_rank_delta <= -10, label "falling"
- If rel_vol_trend = "down", label "fading"
- If no meaningful movement, label "flat"
- If no prior data, label "unknown"
