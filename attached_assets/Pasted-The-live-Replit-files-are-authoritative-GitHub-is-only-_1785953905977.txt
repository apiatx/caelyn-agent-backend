Defect 1 — subtheme_ids uses parent_theme_id instead of classification

The current Watchlist row logic effectively does:

subtheme_ids = [
    theme_id
    for theme_id in theme_ids
    if registry.get(theme_id, {}).get("parent_theme_id")
]

This is incorrect.

parent_theme_id means:

This node has a broader parent theme.

It does not mean:

This node is classified as a subtheme.

Several legitimate existing nodes have:

classification = "sub_theme"
parent_theme_id = null

Examples include ai_networking, banks, biotech, and other standalone subthemes that have not yet been attached to a broader parent theme.

Those IDs must still appear in subtheme_ids.

Required correction

For every Watchlist row:

subtheme_ids = [
    theme_id
    for theme_id in theme_ids
    if registry.get(theme_id, {}).get("classification") == "sub_theme"
]

Apply the same rule everywhere identity fields are recomputed, including:

normal saved-analysis rows
missing-append rows
skeleton rows
uncategorized reclassification
any reachable cached/LKG normalization path

Do not use the existence of parent_theme_id as a classification proxy anywhere.
