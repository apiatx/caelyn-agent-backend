BACKEND REPLIT AGENT — Make Portfolio vs S&P 500 track actual trade history, not just current holdings

The Portfolio Terminal is working well now. Do not rebuild the portfolio system. Build on what already exists.

New goal:
The Portfolio vs S&P 500 chart on Portfolio Terminal should track the user’s actual portfolio gains/losses over time, based on trade open/close dates and trade history, not just the historical price performance of the current holdings basket.

Current problem:
The chart appears to use current active holdings and historical prices. That makes it look like the current basket existed for the entire chart period. This is not accurate when the user added/removed positions over time.

Desired behavior:
Portfolio vs S&P 500 should reflect:
- active holdings with entry/open dates
- closed trades with entry/open dates and exit/close dates
- entry prices
- exit prices
- shares
- realized and unrealized P&L
- portfolio value over time
- S&P 500 benchmark over the same dates

Important:
Closed Positions already exists on Portfolio Dashboard and appears to be working. Current holdings also exist and are synced to Neon. Build off this. Do not create a competing portfolio store.

Do NOT:
- break current Portfolio Dashboard
- break closed positions
- break Neon canonical active holdings
- break Terminal analytics
- fake portfolio history
- assume the current holdings existed forever
- hardcode tickers
- remove the current chart unless replacing it with the accurate ledger-based chart
- rebuild all analytics from scratch

Algorithm expectation:
For each date/timestamp in the chart period:
1. Include only trades active on that date:
   - active holding if date >= entry_date
   - closed trade if entry_date <= date <= exit_date
2. Value each active trade using historical price on that date.
3. For closed trades after exit_date:
   - do not keep marking them to market.
   - realized P&L should contribute to portfolio value/cash if the model supports cash.
4. Compare portfolio return vs starting portfolio value for that period.
5. Compare to SPY return over the same period.

Important modeling note:
If there is no cash ledger/deposit/withdrawal tracking yet, be transparent:
- Reconstruct trade-level return using deployed capital/trade P&L.
- Mark output as estimated=true.
- Include warning: “No cash/deposit ledger; chart is trade-ledger reconstructed.”
Do not pretend it is a perfect brokerage account equity curve unless account value snapshots/cash flows exist.

Better if already possible:

If not, use trade-ledger reconstruction as current implementation.
