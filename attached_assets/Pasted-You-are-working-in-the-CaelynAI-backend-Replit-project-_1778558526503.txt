Task 3 — Atomic feature pass publication
Avoid publishing half-computed rows.

Implement or verify this pattern:
1. Fetch raw Hyperliquid data.
2. Update snapshots.
3. Compute all feature/signal fields into a temporary batch object.
4. Validate the batch.
5. Only after successful completion, publish/swap it as the active computed signal state.

If a new feature pass fails or is incomplete:

- log the failure
- do not replace good fields with nulls

This matters more than perfect freshness. Stale-but-valid is better than fresh-but-blank.
