PART 1 — TICKER-SUBJECT RELEVANCE GATE
======================================

Before an RSS article can contribute to Catalyst V2 for a ticker, it must pass a deterministic ticker-subject relevance gate.

Being present in that ticker's RSS feed is NOT enough.

An article is eligible for ticker Catalyst V2 only if one of these is true:

A. Title directly mentions the ticker symbol or company name / normalized company alias.

B. Title directly mentions a known subsidiary / acquired business that belongs to the ticker.

C. Title directly describes a partnership/deal involving the ticker's company.

D. Article is an official press release or source strongly associated with the ticker and title is company-specific.

E. Existing archive metadata proves the article was collected from a ticker-specific feed and the title's primary company/entity matches the ticker.

Reject or strongly downweight:

sector roundups

market commentary

peer-company articles

articles where the ticker is merely mentioned incidentally

articles whose primary named company is a different ticker

articles about broad ETFs/indices

generic analyst/market articles

Examples that must be rejected for that ticker:

SNOW:
"Cognizant Strengthens AI Portfolio Through Google Cloud Partnership"

AMD:
"Rackspace Technology (RXT) Is Down 6.6%"

PLTR:
"Rackspace Technology Cuts 2026 Outlook"

DELL:
"Defense AI Heats Up: BigBear.ai Lands First European Validation"

RCAT:
"Nasdaq, S&P 500 Futures Cheer Iran Breakthrough"

IPI:
"CFO granted restricted stock" should not become commercial_contract.

Use only existing cached context:

ticker

company name if available

sector/industry if already loaded

RSS source/title/summary

URL/source

Do not call providers for company aliases.

If company name is not available for a symbol, use a conservative fallback:

allow symbol/title exact match

allow exact ticker in parentheses

allow existing high-confidence ticker mapping if present

otherwise reduce confidence or reject ambiguous sector articles.

PART 2 — PRIMARY SUBJECT / ENTITY MISMATCH HANDLING
===================================================

Add deterministic safeguards against article-subject mismatch.

If the headline clearly identifies another company as the event subject, do not apply the catalyst to the current ticker.

Examples:

"Fermi America Sinks 11.5% with $375M Offering"

should apply to Fermi / FRMI only, not CEG, GEV, OKLO, SMR, etc.

"Rackspace Technology Cuts 2026 Outlook"

should apply to RXT/Rackspace, not AMD, PLTR, RBRK.

"Cognizant Strengthens AI Portfolio Through Google Cloud Partnership"

should apply to Cognizant, not SNOW.

"Nvidia partnership article"

should not automatically become a PLTR catalyst unless Palantir is actually a named partner or the relationship is directly Palantir-specific.

Implement with simple deterministic rules:

extract explicit ticker-in-parentheses patterns like `(RXT)`

extract leading company phrase before verbs like:

announces

wins

lands

signs

partners

acquires

cuts

raises

sinks

reports

launches

selected

If extracted primary subject does not match the current ticker/company aliases, mark:

ticker_relevance = false

or:

ticker_relevance_score <= 0.25

and do not allow COMPELLING/MODERATE Catalyst contribution.

Report every hardcoded alias added.

==================================================
PART 5 — BULLISH / BEARISH APPLICATION RULE
===========================================

Bearish events must pass the same ticker-subject relevance gate.

Do not penalize AMD/PLTR/RBRK because Rackspace had bearish news.

Do not penalize CEG/GEV/OKLO/SMR because Fermi had an offering.

Only apply bearish penalty when the bearish event's primary subject matches the ticker.

If relevance is ambiguous:

keep the event as a low-confidence conflict note if useful

but do not apply the full bearish penalty.
