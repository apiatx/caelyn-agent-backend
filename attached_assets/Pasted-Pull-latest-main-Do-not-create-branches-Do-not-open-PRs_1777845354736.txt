This is an urgent backend stabilization and cost-control pass for Screener Hub + FMP usage.

Main problems:
1. FMP usage is spiking badly. The FMP dashboard shows /stable/historical-price-eod/full is one of the biggest consumers by bandwidth and requests, with large over-limit percentage. We are already over halfway through the 30-day bandwidth limit after only a few days.
2. Screener Hub thematic dropdowns can fail with 502, example:
   /api/screener-hub?tab=thematic&theme=drones&scoreMode=true&cocFilter=false
3. Semiconductors Thematic Screener is still too mega-cap/leader-heavy and is weak for hidden-gem discovery, but fix cost/stability first.

Scope:
Backend only.

Part 1 — Stop FMP historical overuse immediately

Find every backend path currently calling:
- /stable/historical-price-eod/full
- any FMP full historical endpoint
- any FMP historical endpoint inside Screener Hub, theme RS, returns warm, or related jobs

Requirements:
1. Normal page loads and dropdown changes must not trigger heavy FMP historical fetches.
2. Screener Hub requests must use cached returns from screener_returns_cache.
3. If cache is cold, return null RS/performance fields with rs_data_status="cache_cold" or "partial", not a live full-history fetch.
4. Historical return warm jobs should fetch only the minimum range needed:
   - max 120 trading days / about 180 calendar days
   - enough for 2w, 4w, 10w returns plus buffer
5. Do not use /stable/historical-price-eod/full for Screener Hub RS.
6. Prefer a lighter/ranged FMP historical endpoint already supported in the codebase. Use from/to date params if available.
7. Cache by symbol and as_of_date so each symbol's returns are fetched once per day/week, not per request.
8. Dedupe symbols across all Screener Hub tabs before fetching returns.
9. Never overwrite good cached returns with empty/failed responses.
10. Add logging/metadata showing endpoint_group="historical_returns" and symbols fetched/skipped.

Part 2 — Add/finish FMP governor

Implement or complete a lightweight FMP budget governor.

Requirements:
1. Per-minute RPM limit:
   - env FMP_RPM_LIMIT default 120 for now, not 240
   - We are conserving bandwidth, not stress-testing FMP.
2. Call spacing:
   - env FMP_CALL_SPACING_SECONDS default 0.75
3. Per-job soft limit:
   - env FMP_JOB_SOFT_LIMIT default 500
4. Daily soft limit:
   - env FMP_DAILY_SOFT_LIMIT default 2500
5. Monthly/bandwidth awareness:
   - Add env FMP_MONTHLY_SOFT_CALL_LIMIT if easy, default 50000
   - Add metadata hooks for bandwidth-sensitive endpoints, especially historical.
6. If job budget is hit:
   - stop gracefully
   - mark job partial_budget_limit
   - preserve completed rows
   - serve stale cache
   - do not crash endpoints
7. Add admin status output:

     enabled,

     call_spacing_seconds,
     job_soft_limit,
     daily_soft_limit,
     latest_jobs,
