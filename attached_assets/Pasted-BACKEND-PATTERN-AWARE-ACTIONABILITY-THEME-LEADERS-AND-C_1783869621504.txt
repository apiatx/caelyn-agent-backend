Backend only.

Do not touch frontend.
Do not call LLMs.
Do not add request-time provider calls.
Do not add new scoring producers unless required.
Do not remove existing fields.
Do not rebuild Catalyst, Options, Investment, or Entry from scratch.

Goal:

Fix remaining Confluence/Actionability flaws:

1. WYFI-style high-tight continuation setups are incorrectly classified as TOO_EXTENDED.
2. LITE-style leader/support pullbacks may be incorrectly classified as RISK_CONFLICT / BROKEN_SUPPORT.
3. All Confluence currently risks double-counting Catalyst because Trade Alignment already contains Catalyst and CCS adds Catalyst again.
4. Component coverage is incomplete for Entry, Options, and Catalyst; we need root-level coverage/status fields, not patchy UI guesses.
5. Theme leaders pulling back into support should be treated as opportunity candidates, not automatically risk.

Use cached bars, existing Stage/Entry LKG, existing catalyst cache, existing options cache, existing theme data, existing watchlist fundamentals, and existing alignment rows only.

No new provider calls.

PART 2 — ADD CONTINUATION PATTERN ENGINE
==================================================

LOW_BASE_REVERSAL

WYFI-like logic:

A ticker should not be classified as TOO_EXTENDED just because it is far above an old base if:

- price recently had a strong impulse move
- price then consolidated high and tight
- consolidation range is relatively tight vs prior impulse
- price is holding above breakout shelf / current flag support
- active support has shifted up to the current consolidation shelf
- lower_low_confirmed is false
- active_support_status is above_support / testing_support / bounced_from_support
- stage is Stage 2 / S2 breakout / S2-S3 advance
- price is near the upper part of the consolidation and trying to break out

Classify as:

pattern_type = HIGH_TIGHT_FLAG or BREAKOUT_SHELF_CONSOLIDATION
constructive_extension = true
chase_extension = false
entry_risk_reward_state = BREAKOUT_CONTINUATION_READY or CONTINUATION_SETUP
actionability = READY / NEAR_ACTIONABLE / WAIT_FOR_BREAKOUT depending confirmation

Do not force WATCH_FOR_RESET unless:

- price is extended with no consolidation
- no current shelf support
- no flag/base structure
- volume climax without consolidation
- distance from current active support is too high
- lower_low_confirmed or support lost

PART 3 — REFINE EXTENSION LOGIC
==================================================

Separate:

CHASE_EXTENSION
from
CONSTRUCTIVE_EXTENSION

CHASE_EXTENSION:
- vertical move
- no consolidation
- far above current active support
- crowded/volume climax
- no defined invalidation nearby

CONSTRUCTIVE_EXTENSION:
- strong move
- then consolidation
- active support has moved up
- invalidation is nearby
- breakout trigger is identifiable
- no lower low confirmed

Only CHASE_EXTENSION should force TOO_EXTENDED / WATCH_FOR_RESET.

CONSTRUCTIVE_EXTENSION can remain Actionable or Near Actionable if trade/core and entry pattern qualify.

Add fields:

extension_quality:
  CHASE
  CONSTRUCTIVE
  NORMAL
  BROKEN

extension_reason_codes
