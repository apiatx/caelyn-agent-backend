1) VIX Risk Regime tab backend requirements

Payload should include:

A) current_market_snapshot
Reuse the exact existing Home Market Snapshot service/cache. Include at minimum:
- spx/current S&P value
- spx 1D %
- vix value
- vix 1D %
- us_10y value
- us_10y bps or percent change if already available
- dxy value/change if already available
- snapshot freshness/cache_age/source metadata if available

B) vix_regime_signal
Use current VIX level and trend to return a signal object:
- current_vix
- current_zone
- warning_level
- signal_title
- signal_summary
- rules_used

Signal rules:
- VIX < 20: Calm / complacency zone. Profit protection / risk monitoring.
- VIX rising back above 20: risk regime worsening warning.
- VIX 20-30: elevated risk.
- VIX 30-40: stress regime.
- VIX > 40: panic/dislocation regime; long-term opportunity watch, not hard buy advice.

Do NOT write hard advice like "buy" or "sell." Use signal/warning language.

C) vix_spx_correlation
Calculate true rolling statistical correlation between VIX % changes and S&P 500 % changes:
- 1D move side-by-side
- 7D move side-by-side
- rolling_corr_7d
- rolling_corr_30d if data is available
- sample_size
- calculation_window
- last_updated

Use daily historical data. For correlation, use daily percent changes over the selected window. Do not fake correlation from only two points.

D) historical windows
Support these lookback windows:
- immediate: 7 trading days
- short_term: past quarter / about 63 trading days
- medium_term: 1 year
- long_term: 5 years

2) Weekly Price Movements tab backend requirements

This must be deterministic Python/backend logic, not AI calculation.

Use real historical S&P 500/SPY/index daily data, depending on whichever historical source already exists and is reliable in the backend. Prefer the same S&P proxy/symbol already used across the app if one exists.

Compute four scenarios across each lookback window:
- 5y
- 1y
- quarter / 63 trading days
- 7d / immediate, if enough samples exist; if not enough samples, return insufficient_sample=true

Definitions:
A) Red Friday -> Monday outcome
- Friday is red if Friday close < Thursday close.
- Monday outcome is green/red based on Monday close vs Friday close.

B) Green Friday -> Monday outcome
- Friday is green if Friday close > Thursday close.
- Monday outcome is green/red based on Monday close vs Friday close.

C) Red Monday -> rest of week outcome
- Monday is red if Monday close < prior Friday close.
- Rest of week outcome is Friday close vs Monday close.

D) Green Monday -> rest of week outcome
- Monday is green if Monday close > prior Friday close.
- Rest of week outcome is Friday close vs Monday close.

For each scenario return:
- sample_count
- green_count
- red_count
- green_probability
- red_probability
- average_return_pct
- median_return_pct
- best_return_pct
- worst_return_pct
- current_read
- confidence_label based on sample size
- insufficient_sample flag if needed

Also return:
- most_recent_matching_cases, maybe last 5
- current_week_context if today/current week has already created a matching condition
- scorecard_updated_at
- data_source
- cache_age_seconds

AI enhancement:
