BACKEND ONLY — CONFLUENCE V4.2 CONTRACT NORMALIZATION PASS

Backend repo only.

Do not touch frontend.
Do not change Confluence scoring math.
Do not recalibrate actionability.
Do not change canonical history.
Do not run the 10Y backfill.
Do not touch provider logic.
Do not touch Options Flow.
Do not run provider-calling validations.
Do not remove existing legacy fields yet.
Do not break existing endpoints.

Goal:

The backend Confluence V4.2 engine exists and is mostly working, but the API response is noisy and internally contradictory.

The audit found:

- 278 keys per row.
- V4.2 canonical fields are mixed with V4.2 debug copies, V4.0 debug copies, V2 Trade Alignment fields, legacy verdict/grade fields, and disabled prediction/theme-policy fields.
- is_watch_for_reset is unreliable and contradicts caelyn_confluence_bucket on symbols like ABCL.
- Score display guidance is inconsistent: backend exposes total score out of 125, but product UI should emphasize Core /100 + Bonus +X /25, not make /125 the main denominator.
- core_score_max, bonus_score_max, and total_score_max are not cleanly exposed.
- invalidation_level and target fields are nested/inconsistent.
- risk_flags are not returned as a first-class field.
- why_now / why_wait are not implemented.
- fib/wave fields exist but are currently null pending 10Y backfill.
- whale/insider is not wired and should be marked as not_wired.
- frontend needs one clean V4.2 object so it does not accidentally consume legacy Trade Alignment fields.

This pass should normalize the backend contract without changing score math.
