BACKEND REPLIT AGENT — Add edit / partial close / full close support for open option positions

The Portfolio Dashboard now correctly imports and displays open options positions. Next, users need to manage those open options manually from the Dashboard, the same way they can manage core stock positions.

Goal:
Users must be able to:
1. Edit an open options position.
2. Partially close an options position.
3. Fully close an options position.
4. Have closed/partially closed option activity show under the Options toggle in the Trade Journal.
5. Preserve accurate realized P&L, remaining contracts, cost basis, and open option valuation.

Do not rebuild the options import engine.
Do not break stock/core position close/edit logic.
Do not hardcode option symbols.
Do not call frontend-only accounting logic.
Do not mix options into stock positions.
Do not change the global Options Flow page.

Current option data already works:
- option_open_positions
- option_partially_closed_positions
- option_fully_closed_positions
- option_closed_trades
- live Tradier mark valuation
- portfolio_summary option totals

Required backend endpoints:

A. Edit open option position

Add:

PATCH /api/portfolio/options-positions/{occ_key}

Payload fields should allow:
{
  "contracts_open": optional number,
  "avg_premium": optional number,
  "cost_basis": optional number,
  "entry_date": optional "YYYY-MM-DD",
  "expiration_date": optional "YYYY-MM-DD",
  "strike": optional number,
  "option_type": optional "CALL" | "PUT",
  "notes": optional string
}

Behavior:
- Load open option position by occ_key.
- Validate it exists.
- Update allowed fields.
- If contracts_open and avg_premium are supplied, recompute cost_basis unless cost_basis is explicitly supplied.
- Preserve underlying/occ_key consistency unless intentionally editable.
- Invalidate holdings/options caches.
- Return updated option position.

B. Sell / close option position

Add:

POST /api/portfolio/options-positions/{occ_key}/sell

Payload:
{
  "sell_type": "contracts" | "dollars" | "percent" | "full",
  "contracts_closed": optional number,
  "dollar_amount": optional number,
  "percent_closed": optional number,
  "exit_premium": number,
  "exit_date": "YYYY-MM-DD",
  "fees": optional number,
  "close_reason": optional string
}

Behavior:
- Load open option position by occ_key.
- Validate:
  - position exists
  - exit_premium >= 0
  - exit_date valid
  - close amount > 0
  - contracts_closed <= contracts_open for sell_type="contracts"
- Use contract_multiplier = 100.
- Average-cost accounting.

Contract close math:
- contracts_before = contracts_open
- contracts_closed based on sell_type:
  - contracts: exact contracts_closed
  - dollars: dollar_amount / (exit_premium * 100)
  - percent: contracts_open * percent_closed / 100
  - full: contracts_open
- proceeds = contracts_closed * exit_premium * 100 - fees
- cost_basis_closed = avg_premium * contracts_closed * 100
- realized_pnl = proceeds - cost_basis_closed
- realized_pnl_pct = realized_pnl / cost_basis_closed * 100
- contracts_remaining = contracts_before - contracts_closed
- remaining_cost_basis = avg_premium * contracts_remaining * 100

If contracts_remaining > tolerance:
- update open option position:
  - contracts_open = contracts_remaining
  - cost_basis = remaining_cost_basis
  - avg_premium remains same under average-cost accounting
  - final_option_status = "partially_closed_open"
- create option closed trade with:
  - contracts_remaining_after = contracts_remaining
  - is_full_close = false
  - final_option_status = "partially_closed_open"

If contracts_remaining <= tolerance:
- remove or mark open option position as closed/inactive
- create option closed trade with:
  - contracts_remaining_after = 0
  - is_full_close = true
  - final_option_status = "fully_closed"

Closed option trade record fields:

}
