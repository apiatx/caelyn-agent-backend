Part 6 — Scheduling

Implement a scheduler or scheduled job entrypoint that can:

generate a new snapshot on cadence
default cadence = 14 days
allow manual refresh endpoint
allow cadence to be configurable in code/env later

Do not assume background cron exists magically if the deploy environment doesn’t support it cleanly.
If the repo already has a safe scheduler pattern, use it.
Otherwise:

implement a callable generation job
and a “refresh if stale” pattern on request
Safe fallback

If no scheduler infra is reliable, implement:

when latest snapshot is older than cadence
and a user visits page / manual refresh endpoint is hit
backend regenerates snapshot once and persists it

That is much safer than pretending cron always works.
