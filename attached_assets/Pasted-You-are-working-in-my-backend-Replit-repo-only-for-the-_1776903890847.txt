## Target architecture to enforce in backend

This routing policy should become true everywhere in backend logic:

### Primary provider roles

* **FMP** = broad structured backbone for:

  * stock reference/profile
  * fundamentals
  * market cap / float / liquidity where already supported
  * news / event / analyst / ratings / calendar
  * historical daily price data
  * ranking inputs
  * sector / industry / market performance context

* **Tradier** = live equities/options intraday lanes where truly needed:

  * live multi-symbol quote panels
  * short-interval candles
  * intraday technical pipelines
  * options-first workflows
  * fast-refresh equity panels if already wired and appropriate

* **Hyperliquid** = crypto-native / futures-ish / high-velocity market engine:

  * crypto/perps
  * funding / liquidations / order-book-sensitive workflows
  * crypto-native real-time market structure
  * pre-IPO proxy markets already using HL

* **Finviz** = screener/discovery weirdness only:

  * unusual screener combinations
  * periodic discovery snapshots
  * Finviz-specific filtering logic
  * not live quote backbone
  * not intraday engine
  * not patching missing basic quote/reference data if FMP already covers it

* **Public** = options fallback only

### Demoted providers

* **Finnhub** = demote heavily unless audit proves a unique niche
* **TwelveData** = keep only for narrow technical/intraday use cases if Tradier/FMP do not already cover them cleanly
* **Alpha Vantage** = retire from active stock/equity quote/history/news/reference flows unless there is a truly unavoidable remaining edge case
