# Contract 1 — extend the low-level transaction primitive

Use and, where necessary, minimally extend:

```python

```

It must support in one transaction:

1. Upserting `add` or `remove` rows for every affected `theme_ticker_overrides` membership.
2. Setting the canonical primary category override when `primary_theme_id` is non-null.
3. Deleting the canonical primary category override when `primary_theme_id` is null.
4. Replacing an old primary with a new one.
5. Promoting an already-existing additional membership to primary without requiring another membership insert.

Preferred explicit primary operation shape:

```python

    "action": "set",
```

or:

```python
primary_operation = {
    "action": "clear",
    "user_id": "default",
    "ticker": "ALAB",
}
```

Use naming consistent with the live storage module.

Do not overload a missing dictionary to ambiguously mean clear.

## Transaction behavior

Within one connection:

```text
BEGIN
all theme-membership statements
primary set or clear

```

On any statement failure:

```text

no partial state
```

Return a failure result or raise a typed storage exception.

```text

```

## Primary unchanged, additions changed

Do not rewrite the primary unnecessarily, but the final stored state must remain authoritative.
