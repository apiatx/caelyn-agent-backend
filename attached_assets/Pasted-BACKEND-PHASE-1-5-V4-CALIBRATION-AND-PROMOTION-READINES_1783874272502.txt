==================================================
PART 1 — RAW VS NORMALIZED SCORE POLICY
==================================================

Audit V4 scoring fields:

caelyn_confluence_v4_score
caelyn_confluence_v4_raw_score
caelyn_confluence_v4_normalized_score
caelyn_confluence_v4_total_score
caelyn_confluence_v4_confidence_score

If these names differ, report exact names.

Problem:

Buckets are currently driven by normalized score because missing options/catalyst deflate raw total.

That is reasonable, but we need a confidence guard.

Define clearly:

raw_score:
actual points earned out of full possible model

normalized_score:
score adjusted for available components

confidence_score:
how complete/fresh the input set is

Promotion rule:

Do not let a low-confidence normalized score create READY.

Suggested:

READY requires:
normalized_score >= threshold
AND confidence_score >= 70
AND no hard risk
AND entry/actionability confirmation

NEAR_ACTIONABLE can allow confidence_score >= 50 if setup is technically strong.

WATCH can allow lower confidence.

Return top 50 sorted by:
raw score
normalized score
confidence-adjusted score

Recommend which score should be shown in frontend.

==================================================
PART 2 — HARDEN CONSTRUCTIVE EXTENSION
==================================================

Current issue:

WYFI was correctly rescued by HIGH_TIGHT_FLAG + CONSTRUCTIVE.
But CRWD / FTNT / MU / OSCR also became NEAR_ACTIONABLE.

That may be too permissive.

A constructive extension should require real current-shelf evidence, not just “extended + pattern label.”

Add stricter requirements:

constructive_extension can override TOO_EXTENDED only if:

- pattern_type in HIGH_TIGHT_FLAG / BULL_FLAG / BREAKOUT_SHELF / VCP / STAGE2_BREAKOUT
- pattern_score >= minimum threshold
- current_shelf_support exists
- distance_to_current_shelf_support_pct is reasonable
- consolidation duration >= minimum bars
- consolidation range is not too wide
- price is not wildly above shelf
- active_support_status is above_support / testing_support / bounced_from_support
- lower_low_confirmed false
- major_lower_low_confirmed false
- no volume climax / exhaustion flag
- no failed breakout
- no active support lost

If these are not met:

extension_quality = CHASE
bucket = WATCH_FOR_RESET

Do not remove WYFI fix. Make the distinction better.

PART 6 — ACTIONABILITY V4 CALIBRATION
==================================================

Actionability V4 must remain a decision layer, not another score.

Calibrate:

READY:
high V4 normalized score
confidence sufficient
valid entry pattern
not chase extension
not confirmed risk

NEAR_ACTIONABLE:
good V4 score
valid setup
may need breakout/retest/confirmation

WATCH_FOR_RESET:
chase extension or too far from current shelf

AVOID:
confirmed breakdown / active support lost / major lower low

WATCH:
incomplete or insufficient confluence

Return bucket/actionability distribution before and after calibration.

Target:

ACTIONABLE should not be zero, but should be selective.
NEAR_ACTIONABLE should surface good setups.
WATCH_FOR_RESET should capture true extended/chase names.
RISK_CONFLICT should stay reserved for confirmed breakdown/risk.
