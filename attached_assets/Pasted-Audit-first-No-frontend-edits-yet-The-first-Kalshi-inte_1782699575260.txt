Backend summary says “Polymarket always wins if it finds a match.” That is no longer the desired behavior for finance/index/equity/commodity markets.

4. Provider selection / duplicate handling

If multiple providers or multiple Kalshi events match the same family:

* choose the highest-quality market based on:

  1. higher volume_24h if available
  2. higher total volume
  3. higher open_interest
  4. better liquidity
  5. closer/current relevant date for daily/tomorrow contracts

Rule:
If there is a duplicate market, always take the higher-volume one unless it is closed/stale.

Change prior behavior:
Do not let Polymarket automatically beat Kalshi for these finance families.
For finance/index/equity/commodity families, Kalshi should win if it has the cleaner/higher-volume active market.

Keep Polymarket primary for:

* Fed decisions/cuts/hikes
* recession
* unemployment/CPI if no better Kalshi equivalent
* geopolitics
* AI benchmark/Chatbot Arena
* BTC price milestones unless Kalshi has a better liquid equivalent
* weird company-specific milestone markets where Kalshi has no equivalent
